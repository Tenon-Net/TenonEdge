# 新连接类型：版本化草稿与共享运行

T3-10 子场景。当前已接通**编译期连接声明 → 认证发现/非秘密草稿/业务key导入导出 → 冻结连接 → 已注册输入模块 → 原共享连接/出站检查/监督者 → 原队列及HTTP输出**。独立凭证、网页自动表单与任意新输出传输仍未完成，不能把这一软件子场景当作T3-10或T3交付完成。

## 声明和准入

`ConnectionModuleDefinition`是适配器的辅助元数据，通过Host的原DI显式注册；不是第四类可执行扩展，不安装、扫描或热加载程序集。它声明kind、正整数version、显示名及Connection用途的`ParameterSchema`。类型遵守原运行单元kind的小写点分段规则；不能覆盖http/mqtt/modbus/tenon，同kind/version不能重复注册，不自动采用最新版本。

`ConnectionModuleCatalog`只持有不可变声明。`Freeze`先按声明校验，再生成`ModuleConnectionSnapshot`；参数保留精确JSON数字，拒绝未知、重复、范围错误的属性，默认值不隐式填入。当前没有新连接的受保护凭证或嵌套连接解析入口，因此需要这些状态的必填声明会拒绝准入，不能凭种子文件自报“已设置”。普通参数中出现Credential字段（包括null）仍被拒绝，不把秘密存进运行快照。

适配器使用的`ReadModuleConfiguration`和`ModuleConfigurationIdentity`随`ModuleConnectionSnapshot`放在Abstractions中，只依赖BCL；不要求Adapters反向引用Runtime来读取快照或计算共享身份。声明目录与宿主准入继续属于Runtime/Host。

连接实例仍由`ISharedConnections`持有，工厂只构造本地对象；协议语义由适配器在纯构建阶段校验。联网必须借用共享租约并经`IOutboundConnector`执行实际IP出站检查；超时、取消、串行执行、最后释放及观察机制沿用原契约。受信任代码不是沙箱，不允许把秘密伪装为普通文本参数。

## 冻结格式与历史

下例是内部运行快照片段，**不是配置导入文件**，也不是产品自带的新业务协议：

```json
{
  "connectionId": 10,
  "kind": "testwire",
  "configuration": {
    "connectionModule": {
      "version": 1,
      "parameters": { "host": "127.0.0.1", "port": 19001 }
    }
  }
}
```

输入模块仍按原参数名引用连接ID字符串，并通过`InputUnitContext.Connections`获取冻结快照。声明注册本身不放行示例回环地址；实际网络访问仍需要部署/网页出站授权。

- 新种子、冻结、人工重试及运行构建使用当前宿主目录验证连接类型/版本/参数；另一目录已解析的计划或历史结构读取不能绕过本机准入。
- 历史读取只核对冻结结构、上限和快照哈希，不执行模块或要求连接声明仍已安装。参数最多128项、128KiB，必须为标量对象；不改写旧格式或内容哈希。
- 类型声明缺失时，启动仍加载原有效快照；原准备机制仅将引用它的单元标记为构建失败，其他输入和已冻结队列发送继续。恢复正确声明后按原快照启动。
- 共享会话配置身份包含kind、version和全部冻结参数，不把变更后的参数误借给旧会话；**这个身份不是输出接收方指纹**，不能拿它替代凭证账户、目标变更或迁移保护。
- 同一连接ID的协议/参数必须一致，与内置协议交叉冲突也拒绝。新连接计入原500个全局上限及管理员收紧后的计划准入限制。
- 统一连接查询纳入这些冻结引用、使用者和共享通信观测，不执行协议或回显参数。未实现的通用目标描述明确显示“目标由适配器解析”，不从任意标量猜地址；旧种子仍没有可编辑草稿。

## 草稿、导入与编译

认证后的三种角色均可通过`GET /api/edge-admin/v1/connection-modules`读取固定版本的声明，响应`no-store`；发现不执行适配器。默认产品没有测试协议声明。创建/更新继续使用原`/connections`管理API，只允许配置人员及管理员，并沿用Cookie/CSRF、全局草稿版本、唯一业务key与原子审计。

请求仍指定`kind`，扩展使用`module`，并在`module`对象里明确真实类型、版本与非秘密标量。例如测试侧声明注册后：

```json
{
  "expectedVersion": "0",
  "key": "wire",
  "name": "测试连接",
  "kind": "module",
  "module": {
    "kind": "testwire",
    "version": 1,
    "parameters": { "host": "127.0.0.1", "port": 19001 }
  }
}
```

这不是产品默认可用协议，也不授予示例地址出站权限。规则如下：

- 保存前按本机精确kind/version声明校验；未知版本、必填缺失、范围错误、重复/未知参数、嵌套对象或秘密字段拒绝，默认值不自动补入。准确保留数字原文。
- 同key的真实协议类型不可变：`module/testwire`不能改成`module/otherwire`或HTTP；明确选择已安装的另一声明版本可以保存，不自动升级。内置协议数据结构不改，旧草稿/快照不会多出`module: null`而改变比较内容。
- 历史/草稿读取与导出只做结构检查，声明卸载后仍可查看、导出或删除无引用草稿。新的保存、导入和启用配置编译必须经当前目录准入。不会在读取时执行模块或悄悄采用最新版本。
- 来源引用仍使用原显式参数名→连接ID，冻结时带出真实kind/version/参数，再经输入目录校验；应用与预检使用同一目录。共享运行计划与完整草稿检查点均保留该版本。扩展输入连接不会被误当HTTP队列发送者。
- 导出保留连接业务key和非秘密版本参数，来源引用换成key；合并/替换导入按本机key匹配或分配新ID，两种模式均禁止同key换真实类型、拒绝缺声明/版本。没有新类型凭证支持时，导入不能伪报凭证比较摘要或接受秘密。
- 删除仍经原事务复核设备/来源/路线、保留有效/上一/待定版本及三分区投递；核对或查询不是授权绕过。移除草稿使用者不解除有效快照的引用保护。
- 当前网页列表可安全列出类型/版本，但禁用扩展草稿的内置协议编辑入口并明确提示尚未接入。**此兼容保护不是自动表单交付**，不把任意参数交给Modbus/MQTT表单解释。

## 实际验证与尚缺部分

测试侧实现一个有界的8字节响应协议，两个输入共享一个真实TCP会话，收到超过2^53的整数后经原SQLite队列发送HTTP；未放行的本机端口被原出站规则拒绝。三次正常Host生命周期验证共享释放、卸载连接声明、单元降级、原HTTP待发正文/编号补发和恢复。它不是产品协议、实物/物理断电、TLS或新类型凭证验证。

新增草稿链路验证覆盖角色/CSRF、精确数值、乐观并发、类型不可变、审计失败回滚、卸载后的读取/导出，以及两种导入模式的本机ID重映射。真实TCP链路从认证连接API、原设备/来源/路线存储和跨Host导入开始，显式应用后双输入共享会话；卸载连接声明正常重启，原HTTP冻结正文/编号仍可补发，未应用草稿不被覆盖。它含API/内部服务测试夹具，不是浏览器无JSON全流程或强杀/物理断电。网页新增用例只验证模拟模块列表响应不会打开错误的内置协议编辑器。

独立受保护凭证、账户/换址核对及积存保护、六类自动表单仍须继续。输出模块仍委托原HTTP/MQTT工厂，没有放宽为直接发送新传输，也未绕过其接收方指纹/迁移保护。可发布扩展示例与完整开发指南仍属于T5-06。

实际命令、环境和验证证据见实施状态§2.284（冻结运行基础）及§2.285（版本化草稿与原链路）。
