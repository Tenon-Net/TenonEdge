# 连接列表：草稿与正式通信

T3-04 / 功能 §2.1。`/connections` 是同一个连接列表，包括当前草稿及仅存在于有效运行配置的连接。列表本身不测试目标、不重连、不读取消息正文、不应用草稿。

## 如何核对

- **有效配置 / 当前草稿**分别显示名称、业务 key、协议与目标。状态始终对应有效配置，不把未应用地址当成实际运行地址。超时、请求头等未显示的非秘密参数变化也会标记“有未应用的连接变更”。
- **通信状态**取自原共享会话：正式操作成功才显示已连接；启动中为连接中，实际通信或相关运行单元故障为降级。单元 Running、连接测试成功和 socket 存在都不冒充正式通信成功。禁用、未使用、未应用和未知单独显示。
- 最近成功不保证查询瞬间远端仍存活。HTTP/Modbus不为列表额外探测；MQTT按原保活/发布/断开事件更新。Modbus单个从站超时不等于共享连接故障；设备读取状态到设备诊断核对。
- **使用者**可展开全部有效/草稿引用，分别列输入来源、路线输出、停用及未进入当前执行计划的引用。仅补发冻结队列的执行单元不是虚构的路线使用者。扩展模块的引用只读取结构，不调用扩展代码。
- **待发记录**是同一原发送缓存的真实 pending 数量，不含失败区、隔离区；HTTP/MQTT没有待发时为0，队列不可读为未知，Modbus不适用。暂停、退避、隔离和发送控制继续使用“输出诊断”，不另建发送者。
- **最后错误**为固定安全分类与时间，不含异常文本、对方正文或凭证。恢复成功后保留上次错误，重建会话后重新观察。HTTP对方错误摘要仍须在原受保护正文入口查看，只读角色不获额外权限。

已有schema1种子可能没有完整草稿及业务key：显示真实冻结目标及内部编号，不捏造key或可编辑参数；无法比较完整参数时明确提示。没有实际草稿的行不可编辑或删除。

## 刷新及失败边界

管理API `GET /api/edge-admin/v1/runtime/connections` 对所有已登录角色提供非秘密元数据，使用原授权组，返回 `Cache-Control: no-store`。可传 `expectedDraftVersion`；草稿或运行版本在读取期间改变返回409，损坏有效快照也返回409，不能拿草稿替代有效配置。旧 `/connections` API仍仅提供可编辑草稿。

页面每5秒读取，离开页面后停止轮询。网络、500、409或版本失配时，不把缓存的已连接状态继续显示为正常；本地未保存编辑保留，须刷新核对，不自动应用或重放写操作。配置、共享会话与队列分别短时读取，**不是跨两库及网络的原子快照**，数量和状态可能继续变化，页面显示采样时间。

软件与真实浏览器证据见[实施状态](implementation-status.md) §2.281；API夹具、回环HTTP软件对端不等于完整无代码流程、真实设备或整个T3验收。

## 删除前完整核对

列表行发起删除后，先调用 `GET /connections/{id}/deletion-review?expectedVersion=…` 并展示设备/来源、路线草稿、effective/previous/pending 保留版本中的所有冻结单元，以及 queue.db 同一连接的 pending/failed/quarantined 精确计数。设备与路线同时显示停用项，不把“当前未启用”解释为不再引用。核对 API 是短时只读快照，不保留删除授权；查询失败、草稿代次失配、损坏历史快照或队列不可用时禁用确认。DELETE 仍在原配置事务中重查全局草稿版本、全部草稿和保留引用、三个队列分区，并原子删除凭证/信任/审计；核对与提交之间新增的引用或积存仍由服务端拒绝。响应丢失只允许先刷新查询，不自动重放。
