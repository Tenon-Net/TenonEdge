# 纯转换模块运行接线（T3-10 子项）

当前已接通**编译期注册 → 网页发现与自动表单 → 草稿保存/导入 → 图编译/字段传播/预览 → 冻结计划 → 原运行时、持久队列与 HTTP/MQTT 发送者**。不新增运行引擎，不扫描或上传 DLL，不支持脚本、热加载或网络/数据库转换。

自动表单仅覆盖已安装且声明标量参数的纯转换，不能代替任意复杂模块的专用编辑器。输入/输出扩展仍未完成；完整扩展示例和开发指南仍属 T5-06。T3-10 和 T3 均未完成。参数声明基础见[参数说明](parameter-schemas.md)，注册运行基础见[实施状态 §2.266](implementation-status.md#2266-t3-10-纯转换模块注册冻结与运行接线2026-10-16)，画布纵向接线与验证见[§2.267](implementation-status.md#2267-t3-10-转换模块画布草稿编译与真实发送接线2026-10-18)。

## 模块契约

`TenonEdge.Abstractions.Contracts` 提供：

- `IMessageTransformFactory`：稳定的 `Kind`、正整数 `Version`、公开 `DisplayName`（默认 kind）、可选标量 `ParameterSchema`，以及纯本地 `Build(JsonElement)`。
- `IMessageTransform`：不可变的输出字段定义、所引用的字段、结果/工作预算，以及只处理当前消息的 `Apply(EdgeMessage)`。
- `MessageTransformResult`：消息、本阶段无效/缺失字段计数及可选逐字段 `Issues`。消息为 null 表示必填失败，本路径停止，后续阶段不能用常量掩盖失败。

在 Host 编译期装配中注册 `IMessageTransformFactory` 单例，统一的 `TransformCatalog` 收集这些工厂。内置 `transform.map` 版本 1 始终存在，不允许重复覆盖同一个 kind/version。目录、种子准入、版本冻结和唯一 `RuntimeHost` 共用同一注册结果；不持有请求作用域服务、`HttpContext` 或数据库事务。

模块是**可信代码而非沙箱**。工厂/处理器必须无外部 I/O、无跨消息可变业务状态，支持并发调用；不能将秘密放进普通参数、声明或异常。声明中的默认值不自动注入。标量配置先经同一 `ParameterSchema` 校验，再调用工厂编译；复杂映射使用专用规则校验。复杂扩展若无标量声明，必须自行严格检查配置属性、类型、长度和范围，不能据此假定能自动生成网页编辑器。

此纯转换入口不接受凭证或连接引用声明：没有受保护凭证写入流程，也没有当前连接事务快照供引用校验。后续输入/输出/连接扩展不能照搬这项限制来省略其六类参数要求；本批没有改变已有连接参数的六类契约。

## 画布、草稿与预览

- 所有已登录角色可读 `GET /api/edge-admin/v1/transform-modules`，响应禁止缓存；画布按 kind/version 发现已安装且可配置的转换，名称直接显示为文字。创建节点时显式填入声明默认值；加载已有配置不自动填默认值或换版本。
- 只读不能编辑；配置人员/管理员沿原路线草稿、预览和应用权限操作。标量表单使用同一参数声明；文字、数字、开关、选项不需要逐模块编写前端。凭证与连接引用仍不属于纯转换。
- 缺必填、类型/范围/整数/选项错误允许保存未完成草稿，但编译、应用严格拒绝。未知属性、重复属性、嵌套对象/数组、配置超限及缺失模块/版本拒绝保存或导入。保存不调用模块 Build，不在配置事务内执行模块代码。
- 自定义版本随草稿、复制、撤销/重做和导入导出保留。模块目录失败或缺少所选版本时保留图与未确认表单，不静默切换模块；可重新读取或明确放弃当前参数编辑。历史/导出只做结构检查，不调用已卸载模块。
- 导入只按实际输入/输出上下文重映射来源与连接引用；纯转换普通标量即使名为 `connectionId` 或 `sourceIds` 也不当成内部编号。精确整数、小数与数字原文保持。
- 字段传播、图编译、应用预检、运行准备和手工/现场样本预览共用宿主目录。逐阶段预览使用同一个有界执行包装，保留内置映射逐字段问题；大小错误仍为 `preview.size`，不泄露模块异常正文。预览不访问输出、不入队。
- 全内置 map v1 图仍生成原 `mappingStages`；包含自定义转换的链生成明确 kind/version/configuration 的 `transformStages`，不迁移旧计划哈希。

## 冻结格式与兼容

原 `mapping`（单规则数组）和 `mappingStages`（规则数组序列）保持兼容，原内容及哈希不迁移。新输出配置可使用 `transformStages`：

```json
{
  "transformStages": [
    {
      "kind": "transform.map",
      "version": 1,
      "configuration": {
        "rules": [
          { "target": "temperature", "type": "number", "sourceField": "raw", "scale": 0.1 }
        ]
      }
    }
  ]
}
```

这只是 HTTP/MQTT 输出配置中的转换部分，不是完整种子，也不是画布导入格式。扩展用自己的 kind/version 和非秘密 configuration；版本语义必须稳定，不能用新实现悄悄改变旧版本配置的含义。

- `transformStages` 与 `mapping` / `mappingStages` 互斥，包括显式 null。
- 每条路径 1—48 个阶段；每个描述只允许 kind、version、configuration，配置必须是对象且原文不超过 128 KiB。
- HTTP/MQTT 的 queue-only 发送接续单元不能带任何转换配置；已冻结报文不再转换。
- 所有新冻结入口（含应用、回滚、恢复）均在写事务之前，用已安装目录重新校验。不能把历史读取结果或另一目录解析出的计划绕过这一步；未知模块、版本或非法参数不会写成新的 pending 快照。
- 已持久化快照先核对原哈希，再读取结构。查看历史不运行外部扩展代码，也不因卸载模块而丢弃原配置或改写哈希；内置规则和阶段结构仍校验。
- 有效快照启动时沿原 `RuntimeHost.Prepare` 逐单元校验：所需转换模块缺失、版本不兼容或构建失败，只使依赖它的输出单元 `BuildFailed`，其他输入/输出继续；不会跳过该转换生成新报文。新种子、冻结、回滚和人工重试仍须严格通过模块校验；不把缺模块的快照当空配置，也不将其误认作可以走损坏快照恢复的证据。重新安装正确的编译期模块后可按原快照恢复。
- 已冻结投递不依赖转换模块重新执行：同目标仍有健康发送者时，旧报文按原编号、正文与地址接续；独立目标没有可用发送者时，原记录保留待发，模块恢复后原样发送。软件与真实浏览器重启验证见[实施状态 §2.269](implementation-status.md#2269-t3-10-转换模块启动故障逐单元隔离2026-10-18)。

## 执行、隔离与预算

原分发器逐路径串行执行转换，再由原输出适配器格式化、冻结投递和入队。旧 `FieldMappingPipeline` 的执行也复用同一转换循环，不维护第二套映射引擎。

- 只允许改变值与质量。来源消息编号、设备/来源标识、采集/接收时间、时间来源、原始 JSON 所有者及诊断元数据必须保留；结果字段/类型须符合编译时声明。不同路径保持独立。
- 扩展抛出的非内存耗尽异常、错误计数、身份变更或超限结果只拒绝该路径，不将异常正文/异常链写进日志或运行事件，不让该消息无限重启分发器。必填失败沿用既有路径计数和失败阶段诊断。
- 每阶段最多 1000 个输出/引用字段，结果预算最多 4 MiB，工作预算至少覆盖结果且最多 32 MiB；沿用的原始 JSON 不重复计入结果预算，其余消息开销按 `BudgetBytes` 保守计入。
- 管线工作预算取相邻阶段“上一结果 + 当前工作区”的最大值；不按全部阶段或路径累加。继续使用原在途预算，准备时拒绝超过运行时配置上限的转换工作区。内置单/多阶段仍分别为 8/12 MiB。
- 这些是准入和逻辑预算，不是 CLR 堆/CPU 沙箱或硬件容量承诺。可信模块必须在分配时遵守声明，不能靠事后结果检查防御无限循环或任意分配。
- 持久队列只保存最终冻结报文。重启、重试或修改转换配置均不重新处理旧记录，不改变旧投递编号和原正文。

新增独立转换只存在于测试代码中，用于证明无需修改分发器即可执行真实处理；未把它作为新业务节点或可导入的产品样例发布。
