# API 令牌（T3-09）

管理员在 **API 令牌**（`/tokens`）中创建、查看和吊销令牌。实际验收与剩余项见 [实施状态 §2.221](implementation-status.md#2221-t3-09-https-api-token真实认证用户联动与页面2026-10-14)。不代表 T3 整体或首版发布完成。

## 创建和使用

1. 使用可信 HTTPS 地址登录管理员账号，核对系统信息显示的证书 SHA-256 指纹。HTTP 页面可以查看元数据和确认吊销，但不能创建令牌。
2. 填写用途名称，选择管理员、配置人员或只读角色；有效期可以不设。页面中的到期时间按本地时区输入，服务端按自己的时钟检查有效期。
3. 创建响应只返回一次原文。保存到调用方的秘密存储后关闭原文；页面不写 localStorage、sessionStorage、URL、查询缓存或 mutation 缓存。刷新、关闭或丢失响应后不能找回，须核对清单、吊销该项、换名重新创建。**不要自动重试创建。**
4. 调用管理 API 时使用 `Authorization: Bearer <令牌>`。只接受 HTTPS，不接受查询串或 Cookie 形式的令牌；经 HTTP 携带 Authorization 的请求直接拒绝，不跳转。无效 Authorization 不回退到同时携带的 Cookie。
5. 脚本必须信任已核对的服务器证书，不使用 `curl -k`、`--insecure` 或关闭证书校验的代码。以下假定 `gateway.pem` 已经经可信渠道取得并核对指纹；令牌不要直接写进命令历史、脚本文件或日志：

   ```bash
   # EDGETOKEN 由调用方秘密管理方式注入；此处不填写真实令牌。
   curl --cacert gateway.pem \
     --header "Authorization: Bearer ${EDGETOKEN}" \
     https://gateway.example:8443/api/edge-admin/v1/connections
   ```

令牌不能用于 `/setup` 或 `/auth` 分组：不能借令牌兑换来源用户会话，也不能修改该用户密码。令牌写操作不需要 Cookie 的 CSRF 头；Cookie 写操作仍须原防 CSRF 令牌。令牌认证失败独立按可信来源 IP 每分钟 10 次限流，不消耗登录计数。

## 权限、吊销与用户生命周期

- 令牌绑定一种固定角色。后续修改来源用户的角色、停用或删除该用户，不会暗中改变令牌权限；只有过期或明确吊销使它失效。管理员令牌具有同角色的令牌/用户管理权限，创建子令牌时保留原来源账号归属，并另记代建的令牌名称。
- 停用或删除用户前，页面读取该来源账号**全部尚未吊销的令牌**（包括过期项和上述代建项），明确选择保留或一并吊销，再确认用户操作。没有默认选择。清单在确认前变化，服务端拒绝整个操作，要求重新读取。
- 所选令牌吊销、用户变更和审计在同一配置事务中提交或回滚。不会自动恢复已吊销令牌；不会因删除来源用户而删除令牌历史。
- 吊销须二次确认，下一请求立即失效。不撤销已经接管的后台工作；应用、导出、迁移等仍记录接管时的账号和令牌身份。不同令牌即使来自同一个账号，也不能借用彼此的会话归属资源。
- 本批实现的有界规则：名称去除首尾空白后 1–64 字符，不含控制字符；名称不可复用；角色和有效期不可编辑。尚未吊销令牌最多 1000 个（含过期项），吊销后释放名额。列表按键集分页，只含元数据，永不返回原文或哈希。

配置库只保存随机 256 位秘密的 SHA-256 哈希。创建/吊销与审计共用短事务；列表显示最后成功使用时间。账号名及令牌名是历史归属，不是动态用户外键或权限继承。日常备份恢复规则仍按总设计执行，T5 恢复验收不在本批提前声明通过。

## 预览与迁移的资源归属

同一令牌即使由不同HTTP客户端使用，也共享一个预览并发分区；不同令牌及创建者的Cookie会话分区独立，仍共同受全局上限约束。只读令牌不能发起外部测试。吊销会拒绝下一请求，不提前释放仍在进行的I/O所占额度。

迁移准备清单属于创建它的具体令牌；同账号的其他令牌和Cookie会话不能确认或取消，同一令牌换客户端可继续核对。确认消费清单后不能重放；迁移开始/结果审计保留账号和令牌名。已经完成的迁移结果可由其他管理员查询，吊销不会撤销既有迁移。

真实产品Host/Kestrel、校验本地可信证书的HTTPS Bearer、真实HTTP诊断与持久隔离记录迁移的软件证据见实施状态§2.230；不代表外部平台或实物验收。
