# 网页配置 Modbus → 映射 → HTTP

这是 T3 通用网关的一个软件验收场景，不需要手写业务配置 JSON、运行计划种子或调用写 API。测试使用真实 Modbus TCP 软件从站和 HTTP 接收端，**不是 PLC、厂商兼容、实物断电或整个 T3 的验收**。结果与剩余项统一见[实施状态 §2.264](implementation-status.md#2264-t3-网页无-json-业务闭环软件验收2026-10-16)。

## 前提

- 已按 [Web 工程说明](../web/README.md)构建，由原 .NET Host 同源提供页面。
- 管理员完成首次设置；管理员或配置人员可以建立业务草稿，只读账号不能配置或发起现场预览。
- 网关主机能访问设备和接收端，且目标符合出站策略。测试只通过启动参数授权两个自有软件对端的动态本机端口，不放开任意本机端口或公网。真实部署的端口授权仍由管理员核对。
- 下表是人工测试数据，不是任何电表的真实寄存器定义。现场必须按设备手册确认地址、类型、字节序和比例。
- 本场景的 HTTP 与 Basic 密码仅用于隔离测试数据；真实凭证应通过已核对信任的 HTTPS 保护，不关闭证书校验。

## 页面操作

1. **连接草稿**：建立 Modbus TCP 连接 `plc`，填写主机和端口；建立 HTTP 连接 `receiver`，填写接收端基础地址。编辑 HTTP 连接的认证凭证，填写 Basic 用户名和密码，点击“核对凭证变更（不保存）”，核对身份与积存并确认保存。
2. **设备草稿**：建立 Modbus 设备 `meter`，引用 `plc`，UnitId 为 `1`。进入“数据来源与点位”，建立采集组 `readings`，采集周期 **1000 ms**。
3. 使用“添加空行”逐字段编辑点表，地址写法为从零开始的协议偏移，功能码为 `03`：

   | key | 偏移 | 数据类型 | 字节序 | 软件从站寄存器 |
   |---|---|---|---|---|
   | `energy` | 0 | uint64 | ABCD | `0020 0000 0000 0001`，值为 `9007199254740993` |
   | `temperature` | 4 | uint16 | 不适用 | 十进制 `2385` |

   保存来源草稿。保存本身不开始采集。
4. **路线草稿**：新建 `meter-to-http`，勾选“参与静态编译（草稿启用）”；新路线默认不启用，不能漏掉这一步。向画布拖入 **Modbus 输入 → 字段映射 → HTTP 输出**，从端口连两条线。
5. Modbus 输入选择刚保存的设备/来源；映射表添加两行并确认：

   | 目标字段 | 目标类型 | 来源字段 | 比例 | 偏移 | 单位 |
   |---|---|---|---|---|---|
   | `energyTotal` | integer | `energy` | 不填写 | 不填写 | 不填写 |
   | `temperatureC` | number | `temperature` | `0.1` | `-40` | `°C` |

6. HTTP 输出选择 `receiver`，相对路径填 `/capture`，使用默认标准报文，确认输出参数后保存路线草稿。
7. **路线样本预览**：选择该 Modbus 来源，显式确认“现场读取 Modbus 一次并预览”。应显示大整数原文 `9007199254740993` 和换算结果 `198.5`；此时只读取、计算，**不向 HTTP 接收端发送，不入发送队列**。
8. **配置应用**：查看应用变更清单，核对并确认应用。等待“配置已提交并激活”，再查看设备当前值与输出目标诊断；应用成功不等于对端已经确认接收。
9. 在实际 HTTP 接收端核对路径、认证、报文数字原文及 `messageId` / `Idempotency-Key`。关闭浏览器后，Host 应继续采集；正常重启同数据目录的 Host 后，无需打开浏览器或再次应用即可继续运行。

## 自动验证与边界

新增用例 `web/tests/gateway-workflow.spec.ts` 分别由管理员、配置人员完成上述配置；账号创建、临时密码修改和凭证核对也走页面。除只读角色的 403 负向探针外，不使用测试侧写 API；不注入浏览器 store，不修改数据库，不拦截管理 API 返回模拟数据。

测试拥有并清理独立 Host、数据目录、软件对端和浏览器进程。关闭的是**整个自有浏览器进程**，不是仅关闭标签页；重启后在重新打开浏览器之前核对新增读取和投递。只读账号随后检查查看权限、编辑/预览/应用限制、子路由刷新和 API 的 ProblemDetails 404，且有效版本与草稿版本保持不变。

浏览器只放行本 Host 同源请求，其余请求阻断并计数；流程结束要求非同源请求为零。这是浏览器资源依赖检查，**不冒充整机断网安装或长期无人值守压力测试**。此处只覆盖 Modbus TCP → HTTP，其他协议组合、RTU over TCP、扩展表单、完整容量等仍独立验收。

已构建的开发工作区可定向重跑（在 `web/` 执行，将 IP 换为本机网卡地址）：

```sh
TENONEDGE_TEST_URL=http://<本机网卡IP>:18082 \
  npx --yes npm@11.21.0 exec -- playwright test tests/gateway-workflow.spec.ts
```

最低浏览器可另设置 `TENONEDGE_TEST_EXECUTABLE` 指向已核对来源的归档 Chromium 111。归档浏览器只用于隔离测试数据，不用于生产浏览；实际 Chrome、Edge、Safari 的验证状态不由 Chromium 结果代替。
