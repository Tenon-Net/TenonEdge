# 设备草稿：标识建议与删除核对

T3-04 / 功能 §3.2。保存设备、复制、启停及删除仍只修改全局草稿，不自动应用，也不撤回已发往外部的数据。

## 新设备的 key

输入名称时，页面给出符合原业务标识规则的建议：ASCII拉丁字母转为小写，空格等分隔符转横线；重音拉丁字母规范化，其他非ASCII字符用`u`加Unicode十六进制编号表示。例如`Meter One`建议`meter-one`，`电表一`建议`u7535-u8868-u4e00`。不加载拼音服务、第三方库或外部资源。

建议最多64位，避开当前设备列表中的key，重名时追加`-2`、`-3`等后缀并保留长度上限。这是本地建议，**不预留标识**；保存仍由原事务检查全局草稿版本、唯一性及保留运行版本中的标识。

手工修改key（包括清空）后，名称变化不再覆盖它；“重新按名称生成 key”是显式恢复自动建议。刷新列表、切换协议不会替换编辑中的key或草稿版本。已保存设备的key不因改名称而改变，前后端均不允许改key。

## 删除前核对

“删除设备”先打开只读核对面板；有未保存修改时，须先保存或重新载入设备。面板显示已保存设备的名称/key、会一并删除的来源草稿数量，以及：

- 引用该设备来源的路线名称/key，包括停用路线；同一路线引用多个来源只列一次。停用不等于解除引用。
- 仍引用该设备标识的有效、上一、待生效运行版本，及其执行单元标识；同一版本指向多个位置时合并显示。不会把没有进入执行计划的停用草稿误报为运行单元。

存在引用时禁止确认删除；只能查看路线或版本后按原配置流程处理，这里不自动改路线、停采、删除历史或解锁标识。核对不读取来源样本、点表、请求头或凭证，不执行扩展模块/协议操作。

仅引用核对完整且无阻挡时，才可再次确认删除。这个核对**不是预留或授权令牌**，`DELETE`仍使用原配置事务重新检查草稿版本、路线及保留版本引用，并原子写审计；即使草稿版本没有变化，期间新增的运行版本引用也不能绕过。

读取失败、快照损坏/缺失、版本冲突不会视为“无引用”；删除失败或回复丢失后核对结果失效，不自动重放。先关闭核对、刷新列表确认结果；未收到成功回复不代表服务器没执行。

API：`GET /api/edge-admin/v1/devices/{deviceId}/deletion-review?expectedVersion=...`，operationId `getDeviceDeletionReview`。已登录三角色可读安全元数据，匿名拒绝；删除权限仍为配置人员/管理员。平台映射尚属T4，不通过本入口提前实现。

实现与软件/浏览器证据统一见[实施状态 §2.282](implementation-status.md#2282-t3-04-设备标识建议与删除引用核对2026-10-19)。不代表T3所有设备、协议或实物验收。
