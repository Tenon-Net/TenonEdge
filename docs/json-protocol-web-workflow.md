# 网页配置 HTTP / MQTT → 映射 → 通用输出

适用于 HTTP 拉取或 MQTT 订阅的已解码 JSON 业务数据。不需要编辑配置 JSON、种子文件或通过脚本写管理 API；上游业务报文仍由设备或独立测试端提供。Modbus 流程见 [Modbus 网页配置](modbus-web-workflow.md)。

## 配置步骤

1. 管理员完成首次设置。管理员或配置人员可以配置路线；只读账号仅查看状态，不能读取诊断正文或触发现场预览。
2. 在“连接”中分别新建 HTTP 与 MQTT 连接。HTTP 填基础地址，MQTT 填主机/端口；实际需要认证时在已保存连接下独立核对并保存凭证。保存草稿不会开始采集。
3. 新建设备，选择 HTTP 或 MQTT 类型，引用对应输入连接。在“数据来源与点位”新建来源：
   - HTTP：填写采集周期及路径，例如 `/readings?floor=1`；
   - MQTT：填写精确 Topic，例如 `workflow/input/meter`，订阅 QoS 1。默认忽略保留消息，不把旧保留值冒充新采样。
4. 在字段表逐项填写 key、JSON 定位和类型，也可按已有样本推断流程生成后核对。若上游含采样时间，填写时间定位并选择其真实格式；不要把网关接收时间当作设备采样时间。
5. 新建路线，启用草稿，拖入对应输入、字段映射和另一协议的输出节点。输入选择刚保存的来源；映射填写来源字段、目标字段/类型、比例、偏移和单位；输出选择连接及相对路径或发布 Topic/QoS。连线并保存路线草稿。
6. 在路线预览中选择来源，显式现场读取 HTTP 一次或抓取 MQTT 一条消息。核对精确数值和输出文本；预览不发送到目标、不入队。这里查看保留样本不改变正式输入的保留消息策略。
7. 打开“配置应用”，核对变更及影响后确认。查看真实后台结果；关闭网页不撤销已经接管的应用操作。
8. 在设备当前值和输出诊断查看正式运行。关闭整个浏览器后网关继续采集和转发；正常重启网关加载持久有效版本，不要求再次打开页面或重新应用。

## 软件验收样本

测试上游提供的业务报文（不是网关配置文件）：

```json
{"energy":9007199254740993,"temperature":2385,"sampleTime":"2026-01-02T03:04:05Z"}
```

- `/energy` 声明为 integer，映射到 `energyTotal`，输出仍为数字原文 `9007199254740993`；不能先经 JavaScript 浮点数转换再核对精度。
- `/temperature` 声明为 number，映射到 `temperatureC`，比例 `0.1`、偏移 `-40`、单位 `°C`，结果为 `198.5`。
- `/sampleTime` 按 RFC3339 映射，标准信封保留该时间并标记 `upstream`。独立接收端核对设备 key、投递编号及原始报文字节；HTTP 同时核对 `Idempotency-Key`。

`web/tests/json-protocol-workflow.spec.ts` 使用生产 Host、独立真实 HTTP 对端和 Docker Mosquitto。配置写入来自可见控件；API 只做只读核对和只读账号的拒绝探测。每种输入分别由管理员/配置人员创建，再由新浏览器中的只读账号验证限制；另核对预览不外发、整个业务浏览器退出、原 Host 正常重启、同源资源、子路由刷新和 API 404。

测试的匿名 Broker 仅绑定回环测试端口，Host 的本机出站例外也仅针对自有测试对端；不是生产部署模板或默认放宽规则。实际命令、浏览器版本、结果和未完成范围统一见 [实施状态 §2.302](implementation-status.md#2302-t3-0511-画布节点放置修复与-httpmqtt-网页闭环2026-10-19)。软件接收端不是真实设备兼容验证，正常进程重启不是断电测试，关联场景通过也不等于整个 T3 完成。
