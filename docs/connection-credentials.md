# 连接凭证的保存前核对

适用：T3 连接页中的 MQTT 账号密码，以及 HTTP Basic、Bearer、请求头/查询参数 API Key。[客户端证书](client-certificates.md)采用独立材料上传入口；服务器信任证书不属于身份凭证。

## 网页操作

1. 保存连接草稿，再打开“连接认证凭证”。凭证独立保存，成功后立即生效，不用应用草稿。只读角色不能核对或写入。
2. 选择认证方式，填写用户名/参数名及新秘密，点击“核对凭证变更（不保存）”。这一步只发送公开参数，密码、Token、API Key 值仍留在当前表单，不发送给核对接口。
3. 并排核对原新接收方、认证方式、公开用户名，以及查询时的待发和失败区条数。Token/API Key 没有可见账户标识，API Key 参数名也不是账户标识。
4. 原新认证方式/可见账户相同（或账户不可见）且有积存时，必须明确选择“同一账户的凭证轮换”或“更换了接收账户”；没有默认值，没有积存时不询问。用户名或认证方式变化时，提示旧身份记录会被隔离，不能用“同账户”声明绕过。
5. 勾选影响确认，再点“立即保存凭证”。同账户轮换继续发送；更换账户后，身份不符的待发和失败记录由原发送者隔离，不使用新身份发出。隔离记录不会因为再次保存凭证自动恢复或迁移。

核对是**动态读取，不冻结队列、不授予保存许可**。最终写入仍检查草稿、凭证版本与账户声明：核对后新增积存也可能使保存被拒绝，需要重新读取和核对。实际秘密只在最终写入时校验；核对成功不等于认证成功或连接测试成功。

取消核对、切换认证方式、离开页面及提交结束都会释放本表单中的秘密引用；秘密不进入 Query 操作参数、Zustand、localStorage 或 sessionStorage，不承诺 JavaScript 字符串即时内存清零。冲突或回复丢失后清除秘密并禁止再次核对，先显式读取凭证状态、核对版本与审计；**不会自动重试写入**。回复丢失不能据此认定服务端未保存。

清除凭证仍受保留运行版本引用约束；更换地址默认不能沿用旧秘密，仅管理员可以显式保留并记审计。以上不改变出站规则、TLS 信任或现有身份/冻结发布协调。

## API

`POST /api/edge-admin/v1/connections/{connectionId}/credential-review`

- 需要配置人员或管理员权限、既有 CSRF 保护、原预览并发准入；响应 `no-store`，请求最多 16 KiB。
- 请求包含 `kind`（`http`/`mqtt`）、`recipient`、`expectedDraftVersion`、`expectedVersion`、`authenticationKind`，以及适用的 `username`/`name`。
- MQTT 的 `authenticationKind` 为 `password`；HTTP 为 `basic`、`bearer`、`apiKeyHeader`、`apiKeyQuery`。未知字段（包括 `secret`）拒绝；证书走独立核对端点。
- 返回公开原新身份、查询时刻和动态积存数量、身份变化提示与是否必须声明账户关系；不读取/解密旧秘密，不保存、不联网、不写凭证变更审计。
- 最终保存仍调用原 `http-credential` / `mqtt-credential` PUT，复用冻结发布/入队屏障、版本检查和审计。不要把核对结果当成跳过最终检查的令牌。

## 验证范围

证据统一见[实施状态 §2.263](implementation-status.md#2263-t3-04-密码tokenapi-key-保存前核对2026-10-16)。后端覆盖五种认证、真实待发/失败记录及核对后新增积存；浏览器用独立真实 Host 和本地 HTTP 接收端覆盖轮换、隔离、取消、冲突与丢回复。

浏览器测试通过 API 建立模拟输入路线，再从网页核对和保存凭证；不是完整无 JSON 网页配置验收，不证明实物或全套最低浏览器兼容。MQTT 密码网页保存由关联浏览器验证，MQTT 队列声明由后端验证；不把 HTTP 积存浏览器场景说成 MQTT Broker 实测。T3 整体仍未完成。
