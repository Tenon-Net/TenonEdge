## 1. 选型与适用范围

采用 `satnaing/shadcn-admin` 作为后台界面与工程组织的基础，从固定提交中裁剪所需源码，放入本仓库 `web/`。它不作为后端框架、运行引擎或完整权限系统；TenonEdge 的认证、数据访问、点表和画布按本产品设计实现。

本次固定参考提交为 `e16c87f213a5ba5e45964e9b67c792105ec74d26`，不使用含义随时间变化的 `main` 作为来源记录。T3 采用其他提交时，须记录新提交、改动理由及重新核查的依赖和许可，不因上游更新而自动整体升级。

本文件集中定义前端的新决定。下列旧约定在 `docs/tenonedge-design.md` 第 2.3、3.1、12、19、22 节及相关准备记录中出现时，按本表替代；这些位置的其他约束继续有效。历史评审不改写。

| 项目 | 原约定 | 本次已确认的约定 |
|---|---|---|
| 工程起点 | 新建精简工程，沿用 TenonAdmin React 工具链 | 裁剪复用固定提交的 shadcn-admin，独立维护 web/，不依赖 TenonAdmin 程序集或前端工程 |
| 路由 | React Router（react-router） | TanStack Router，只保留一套路由及其构建插件 |
| 服务端数据查询 | 未单独明确 | TanStack Query，调用统一的 OpenAPI 客户端；不把它当作另一套 HTTP 客户端 |

## 2. 技术组合与职责

| 层次 | 选择 | 职责及边界 |
|---|---|---|
| 基础 | React 19、TypeScript、Vite | 浏览器端应用；Node.js 仅用于构建和测试 |
| 界面基础 | 裁剪后的 shadcn-admin | 布局、主题、导航、公共组件和普通页面的组织方式 |
| UI 与样式 | shadcn/ui、Tailwind CSS 4 | 组件源码在项目内维护，不盲目覆盖已修改组件 |
| 路由 | TanStack Router | 页面导航、路由参数和登录状态引导；不代替后端授权 |
| 服务端数据 | TanStack Query | 查询、缓存、刷新、失效及操作状态；不保存编辑草稿的唯一副本 |
| API | openapi-typescript + openapi-fetch | 从后端 OpenAPI 生成类型，使用统一请求封装；不为迁就模板保留第二套 Axios 请求体系 |
| 本地编辑状态 | Zustand | 画布编辑、选择、撤销重做和其他页面内状态；不保存会话令牌或不可读回的凭证 |
| 表格 | TanStack Table | 普通列表及点表的基础；点表粘贴、校验、编辑和必要的虚拟化另行实现 |
| 表单 | React Hook Form + Zod | 字段校验和表单状态；不把模板示例规则当作后端规则 |
| 路线画布 | React Flow（@xyflow/react） | 编辑与交互；自有图格式和执行语义由 TenonEdge 定义 |
| 文案 | react-i18next | 首版中文，所有产品文案经 i18n，不把 RTL 支持当作国际化 |
| 测试 | Vitest + Playwright | 单元、组件和浏览器测试，具体分工在 T3 工程中落实 |
| 静态检查 | 沿用设计中的 oxlint | 不因模板使用 ESLint 而默认引入重复的检查链；需要额外专项规则时在 T3 记录理由和覆盖范围 |

T3 统一包管理器、构建脚本、格式化和依赖锁文件，只保留一套可复现的安装流程。上游 package.json 中的版本范围不是本项目已经锁定的依赖，也不是已通过兼容性验证的组合。

原浏览器目标保持 Chrome/Edge 111、Safari 16.4、Firefox 128。T3 须同时检查 Vite 构建目标、实际依赖及浏览器 API，不能仅根据 Tailwind 的最低版本推断整套应用兼容。

## 3. 复用与裁剪

| 分类 | 内容 | 处理 |
|---|---|---|
| 复用 | 侧边栏、头部、主题、布局、提示组件、表单和普通表格组织 | 保留所需源码，改为本产品的导航和样式 |
| 改造 | 登录表单、路由守卫、当前用户状态、查询入口、错误处理 | 接入 TenonEdge 的真实 API 和固定三种角色 |
| 独立开发 | 点表编辑、React Flow 路线、配置差异与版本、平台映射和运行诊断 | 按 functional-spec 实现；示例页面不能代替这些功能 |
| 移除 | 模拟用户、模拟 Token、Clerk、社交登录、公开注册、无关演示页面与数据 | 同时清理路由、导入、依赖和构建产物，不只隐藏菜单 |
| 替换 | Google Fonts 外链、示例品牌和站点元数据 | 使用系统字体或经许可核查的本地资源；使用本仓库 TenonEdge 品牌资源 |

导航按功能需求中的总览、连接、设备与点位、数据路线、平台连接、运行诊断和系统设置组织，不因模板有聊天、应用商城或商业仪表盘示例而新增产品功能。

前端的自有图格式不携带 React Flow 私有运行状态；模板不改变草稿、有效快照、节点版本、路径上限或后端编译规则。

## 4. 认证、权限和数据访问

### 4.1 本地认证

使用 .NET 后端的同源 Cookie 会话。首次设置、临时密码修改、登录限流、固定三种角色、安全戳、防 CSRF、HTTP/HTTPS Cookie 及反向代理规则，继续按设计文档第 3.3、10.3 节执行。

- 保留需要的登录表单外观，将示例的邮箱字段和校验改为本产品的账号规则。
- 不保留 mock-access-token、模拟登录成功或 JavaScript 读写会话 Token 的路径；不以 Clerk 或其他外部身份服务作为运行前提。
- 通过后端约定并写入 OpenAPI 的当前会话查询恢复用户信息，不自行假设尚未存在的接口路径。
- 前端可以控制菜单与按钮的显示，但所有 API 权限由后端判定。修改角色、停用和强制下线后的行为以服务端会话状态为准。
- 会话失效或退出时清理相关查询缓存与用户状态，避免其他账号继续看到前一会话的数据。不可读回的秘密不写入本地持久化状态。

### 4.2 API 与错误处理

统一请求封装处理 ProblemDetails、身份状态、取消、超时及防 CSRF。TanStack Query 调用这个封装，不直接依赖模板的 AxiosError 分支。

- 普通查询失败在对应组件显示错误、最后刷新时间和重试入口，不因一次 HTTP 500 就强制跳转到全屏错误页，避免打断未保存的点表或画布编辑。
- 401 按会话失效处理；403 显示权限不足；草稿版本冲突按后端错误码提示刷新与核对，不静默覆盖。
- 后台刷新只更新服务端查询数据，不覆盖用户正在编辑的草稿；草稿和有效配置分别标识。
- 登录、连接测试、真实读取预览、发送测试报文、应用、回滚、清理、迁移、同步、恢复和其他写操作不自动重试（retry=false），也不由页面挂载、焦点变化或自动预加载触发。超时后按相应接口契约确认状态，不直接重放操作。
- 查询是否重试、刷新间隔和取消策略按用途配置；401、403 不自动重试。轮询沿用功能需求的频率，页面离开后停止无用订阅，不引入无限历史缓存。

## 5. 离线、品牌与部署

- 网关管理界面的字体、图标、脚本和样式不得依赖公网 CDN 或外部身份服务；有意配置的设备、Broker 和平台连接不属于界面资源依赖。
- 移除 Google Fonts 的 preconnect 和样式请求；优先使用系统字体。确需打包字体时，先核实再分发许可和包体积，不将外部字体下载作为运行时步骤。
- 文案经 react-i18next，首版提供中文；日期、数量和表单提示按已有产品规则显示。默认 HTTP 下使用到的浏览器能力仍须有已验证的替代实现。
- 标题、favicon、导航品牌使用 `assets/brand/tenonedge/` 及 `docs/brand-assets.md` 指定的资源，不修改原始品牌资产。
- .NET 宿主提供前端构建产物和同源管理 API。部署须验证直接访问、刷新子路由时能返回 SPA 页面；不存在的 API 仍返回正确 API 错误，不能被 SPA 回退成 HTML。
- 不引入 SSR、TanStack Start、独立 Node.js 运行服务或第二套后端；采用 TanStack Router 不改变单 .NET 服务的部署约束。
