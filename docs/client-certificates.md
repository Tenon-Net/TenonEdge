# HTTP / MQTT 客户端证书认证（T3-04 子项）

HTTP 与 MQTT 均已接入原管理 API、连接测试、正式收发/预览及单次测试发送；连接页面现可上传客户端证书、核对公开身份及积存，再明确确认保存。MQTT 已有真实 Broker 与原产品宿主正常重启/冻结队列接续证据；网页测试的 MQTT 对端仅实现 TLS 与 MQTT 3.1.1 CONNACK，不冒充完整 Broker。验证见[实施状态](implementation-status.md) §2.258—§2.262，不代表 T3 整体验收。

## 与服务器信任分开

客户端证书向对方证明本网关的身份，不代表信任对方服务器。自签或私有 CA 服务器仍须按[连接级服务器信任](connection-tls-trust.md)单独核对。两边都保留有效期、用途和链校验；不访问证书里的 AIA/CRL/OCSP 地址，不宣称在线吊销检查。缺必要中间 CA 时须补齐上传链，不能忽略错误。

HTTP 客户端证书仅用于 HTTPS；不与 Basic、Bearer 或 API Key 叠加，也不能随地址保留到明文 HTTP。MQTT 客户端证书仅用于 MQTT TLS（mqtts），不与用户名/密码叠加，不能保留到明文 mqtt；私钥容器不会放入 CONNECT 的密码字段。

## 网页操作

1. 在连接页新建或编辑 HTTP / MQTT 连接，启用 TLS 并保存草稿。仅配置人员和管理员有客户端证书上传入口；管理员的服务器信任操作仍是独立权限。
2. 在“连接认证凭证”中选择“客户端证书”，上传 PKCS#12 / PFX（可填容器口令），或叶证书在前的 PEM 链和未加密 PEM 私钥。页面只显示“已载入”，不回显文件内容。
3. 点击“核对客户端证书（不保存）”：并排查看原认证的接收方、类型和公开账户，以及新证书的主题、颁发者、有效期与 SHA-256 指纹。核对只做本地解析及读取，不连接对方、不写凭证、不推进草稿、不记凭证写入审计。
4. 核对页面显示查询时的待发/失败区条数和时间。身份变化会提示旧记录隔离；同主题且有积存时，必须选择“同一账户的凭证轮换”或“更换了接收账户”，没有默认选项。勾选身份与影响确认后，才能保存。
5. 保存后清除本页材料并刷新状态，后续操作使用当前凭证，不自动应用草稿。可以在连接测试中显式选择已保存凭证，验证对方是否接受该身份。

核对结果**不是冻结清单或保存许可**：运行采集仍可能增加积存，其他用户也可能修改凭证。保存沿用原写入接口，再检查草稿/凭证版本、有效期及账户声明；核对后才新增积存、且未作必要声明时会拒绝，须重新读取、上传并核对。隔离记录不会因保存凭证自动迁移或恢复。

取消核对、清除材料、切换格式/认证方式或离开页面，会释放本页材料引用。保存失败、版本冲突或回复丢失也清除材料，禁用再次核对；须显式重新读取状态，检查版本及审计后再准备，**不会自动重放保存**。材料不进入查询操作参数缓存、Zustand、localStorage 或 sessionStorage；不承诺 JavaScript 字符串即时内存清零。

尚未保存的连接参数也可以临时测试：在 HTTP / MQTT 测试区域选择临时凭证与客户端证书，上传后显式测试。测试不保存证书，结束后清除该区域材料；HTTP 只 GET 基础地址、MQTT 只到 CONNACK。它不是保存前身份核对，也不保证对方业务已持久化。

## 写入与临时测试

脚本可先调用 `POST /api/edge-admin/v1/connections/{id}/client-certificate-review`，传 `kind: "http"` 或 `"mqtt"`、`recipient`、`expectedDraftVersion`、`expectedVersion` 与下述 `certificate`。该入口仅用于客户端证书，返回公开身份及动态积存，不保存私钥；要求现存 TLS 草稿，受原角色、CSRF、256 KiB 请求体和预览并发预算约束。核对不替代最终写入校验。

配置人员/管理员仍用原 `PUT /api/edge-admin/v1/connections/{id}/http-credential` 保存。应通过 HTTPS 管理入口传输私钥，并使用当前登录会话/CSRF 或获授权令牌。例（仅结构示意，不可直接执行）：

```json
{
  "recipient": "https://receiver.example/api/",
  "kind": "clientCertificate",
  "expectedDraftVersion": "当前草稿版本",
  "expectedVersion": "已有凭证版本；首次写入省略此字段",
  "certificate": {
    "pkcs12": "PKCS#12 文件的 Base64",
    "password": "容器口令；无口令时省略"
  }
}
```

也可以把 `certificate` 替换为 `{ "certificatePem": "PEM 证书链", "privateKeyPem": "PEM 私钥" }`。两种格式不能混用；不得同时填写 `secret`、`username` 或 `name`。PEM 必须叶证书在前，随后可带 CA；私钥只支持未加密的 PKCS#8、RSA 或 EC 块。加密 PEM 私钥目前不支持，可改用有口令 PKCS#12。

- PKCS#12 ≤64 KiB；证书 PEM ≤96 Ki 字符；私钥 PEM ≤16 Ki 字符；容器口令 ≤1024 字符、无 NUL。
- 最多 8 张证书，恰好一份匹配私钥；拒绝重复/额外叶证书、尾随数据、CA 作为客户端、错误用途、失效证书及弱密钥。RSA 2048—8192；ECDSA 256/384/521。
- 写入与连接测试请求体均 ≤256 KiB；容器还有 KDF/MAC 工作量限制。超限不截断导入。
- 返回内容仍只有状态与版本，不返回原容器、口令或私钥。写入和账户声明记审计；审计失败则整个写入回滚。

原 `POST /connections/test/http` 选择 `authentication: "stored"` 可使用当前已存证书；选择 `provided` 时，在 `credential` 中传 `kind: "clientCertificate"` 和上述 `certificate` 对象。临时测试不保存材料、不推进草稿版本、不应用配置，只向基础地址发送一次 GET。

### MQTT 写入与测试

使用原 `PUT /connections/{id}/mqtt-credential`，传 `recipient: "mqtts://broker.example:8883"`、`kind: "clientCertificate"`、上述 `certificate`、草稿/凭证版本和必要的账户声明。根级 `username`、`password` 必须省略；容器口令只在 `certificate.password`。旧密码请求可继续省略 `kind`，不改变既有调用格式。

原 `POST /connections/test/mqtt`：
- `authentication: "provided"`：顶层提交 `certificate`，不传根级用户名/密码；只在本次测试使用，不保存。
- `authentication: "stored"`：指定 `credentialConnectionId`，不传临时材料；按原接收方绑定取当前凭证。
- 保留独立随机 ClientId、CleanSession、只到 CONNACK、不订阅/发布的边界。诊断采样另用独立订阅，正式输入/输出仍共用原物理连接。

## 生效与账户边界

保存后下一次操作读取当前凭证，不用重新应用配置。共享 HTTP 会话在凭证版本变化时先关闭旧客户端，再释放旧证书、重建客户端；不会同时保留两套活动会话。切回 Token 等认证时也不继续出示旧客户端证书。MQTT 同样按当前凭证类型重建原客户端，先关闭客户端再释放证书；切回密码不继续携带旧证书。旧运行快照的 `usePassword` 只保留“缺少必需凭证时不得匿名”的限制，不再阻止新凭证立即生效；已作废或无法解密的凭证也不能降级匿名。

同主题换证且已有待发/失败记录时，必须显式提交 `accountChanged: false`（同账户轮换）或 `true`（更换账户），没有默认选择。证书主题变化自动改变目标身份；旧待发记录由原发送者隔离，不能用新账户发送。证书主题、认证类型和随机账户标记参与指纹；证书指纹/版本号本身不改变接收账户。同主题续签不会因此重写原队列字节或投递编号。

保存凭证会先阻止本连接的新报文冻结，等待已有冻结发布交给原写者，再以同一次队列快照核对待发/失败记录，保护持续到凭证提交完成；迁移也参加同一协调。等候超过 5 秒返回 `credential.publicationBusy`（HTTP 409），凭证未更新，请稍后重新核对并保存，不自动重试。等待期间不持有数据库事务，不改变既有账户声明规则。软件验证见实施状态 §2.260；网页和保存前核对见 §2.262。密码、Token 和 API Key 的独立公开参数核对入口及网页操作见[连接凭证核对](connection-credentials.md)（§2.263）；不混用证书材料接口。

更改接收方默认作废认证材料；仅管理员可显式保留到另一个 HTTPS / mqtts 接收方并记审计。显式清除仍受保留运行版本引用保护。过期/损坏材料不降级匿名发送；输出暂停，不作为毒消息累计。

## 持久化边界

配置库 schema 32 在一个迁移事务中扩宽 HTTP 认证类型约束并增加公开主题列，逐列保留旧记录、密文、版本与账户标记。旧 Basic/Bearer/API Key 队列指纹保持兼容。配置导入比较使用证书主题，不以换证版本判定换账户。MQTT schema 33 追加类型/主题列，旧密码行的类型默认为 0，密文、账户标记及版本不动；沿用原保护用途和密文字段。旧 MQTT 密码/匿名指纹与导入账户摘要保持兼容，证书身份使用独立类型域，避免与同文本用户名碰撞。

规范化私钥容器由既有连接级 Data Protection 保护；不写入运行快照、队列、配置导出或日志。容器解码/导出的可变字节缓冲会清零，证书/客户端有明确释放顺序；托管字符串及 BCL 内部句柄由运行时管理，**不承诺所有秘密内存即时清零**。恢复必须保留对应 Data Protection 密钥，不能只复制密文。
