# 输入模块配置与运行接线（T3-10 子项）

当前接通**编译期注册 → 发现与设备/来源自动表单 → 草稿/导入/图编译/预览 → 冻结计划 → 原输入监督者、通道与持久队列 → HTTP 输出**。测试模块仅存在于测试程序集，不作为新业务协议发布。

自包含标量输入和 HTTP/MQTT/Modbus 连接引用已接通来源草稿、业务 key 导入重映射、自动表单与冻结运行；MQTT/Modbus 通过原计划级协议委托复用。输出/新连接类型扩展仍未完成。**T3-10 和 T3 仍未完成**；完整扩展示例与开发指南仍属 T5-06。

## 注册与契约

- 实现 `IInputModuleFactory`，沿用原 `IInputUnitFactory` 的实例生命周期。通过 Host 编译期 DI 只注册 `IInputModuleFactory` 一次；`InputModuleCatalog` 为同一种 kind 的所有版本提供一个原工厂视图，不再重复注册为 `IInputUnitFactory`。
- `Kind` 必须以 `input.` 开头，遵循 `RuntimeUnitId` 的小写字母/数字、点分段规则（最长 64 字符，**不接受连字符**）。同 kind/version 不可重复，不覆盖现有 simulator/http/mqtt/modbus；不同版本可以同时安装，精确选择，不自动升级旧快照。
- 工厂提供正整数 `Version`、公开 `DisplayName`、Input 用途的 `ParameterSchema`，以及纯本地 `Describe(JsonElement)`。字段含 key、类型、可选单位；最多 1000 个，不可重复或含非法标识/类型。
- 声明先校验，再调用 Describe；描述不构建实例，不访问网络/数据库。工厂是受信任、支持并发调用的代码，不是沙箱；参数/字段/异常不能携带秘密。默认值不隐式注入。
- 来源草稿/自动表单接通文本、数字、开关、选项参数和 HTTP/MQTT/Modbus 连接引用。输入不能声明凭证；运行封套须同时提供对应的冻结快照，缺绑定不能准入。MQTT/Modbus 引用须通过下文的原协议委托，不能另建计划级订阅/从站协调。不能以地址或秘密标量绕过连接引用。
- 未委托原协议时，模块的 `Build` / `RecoveryGroup` 收到去掉封套后的原参数，运行单元 ID 和原 `InputUnitContext` 保持不变。原上下文提供激活屏障、时间、读取状态、有界输入通道与共享预算，不新建后台宿主或发送队列。
- 同 kind 的各版本须采用相同 `UsesDurableHandoff`；可重投输入使用原 `ProduceConfirmedAsync`，只在明确接管/拒绝后按协议确认，不能将进入内存当成持久接管。

## 冻结格式

运行计划的输入单元示意（不是网页导入文件，示例 kind 需自行编译注册）：

```json
{
  "kind": "input.example",
  "key": "meter/source",
  "configuration": {
    "inputModule": {
      "version": 3,
      "parameters": { "value": 9007199254740993 },
      "fields": [{ "key": "value", "type": "integer", "unit": "count" }]
    }
  }
}
```

- `configuration` 只允许 `inputModule`；封套包含正整数 version、parameters，以及可选 fields、connections、protocol。参数必须是标量对象，最多 128 KiB；数字保留原文，不经浮点转换。
- 草稿编译时由模块 Describe 冻结并按 key 排序 fields；字段只含非秘密 key/类型/单位。诊断从有效快照读取这些字段，不在 GET 执行模块或从未应用草稿回填。运行准入会核对冻结字段与该版本模块的实际描述一致；不一致时拒绝，不默默换类型。
- 原两属性封套继续兼容；旧种子没有 fields 时不凭空回填或改写历史。
- 旧内置输入与内部工厂的原配置保持兼容，不迁移原快照或哈希。
- 新种子、冻结（含应用/回滚/恢复）和人工重试都重新用当前宿主目录校验。另一目录已解析的计划、历史读取结果不能绕过新冻结；模块代码在配置写事务之前执行。
- 历史读取先核对哈希，再做结构校验，不调用已卸载的模块，不把缺模块当作快照损坏或空配置。
- 重启加载有效快照时，缺模块/缺版本、描述或构建失败由原 Prepare **仅停用该输入单元并显示构建失败**；其他输入和原冻结队列发送继续。重新安装正确版本后，按原有效快照启动，不改历史或重新生成已入队报文。
- 新配置的准备阶段仍是全量准入：任一单元不能构建，不能提交成有效版本；运行后单元异常继续由原监督者按既有停止、释放、退避和单实例规则处理。

验证证据统一记录在[实施状态](implementation-status.md)。本子项的独立输入产生精确整数，经真实 SQLite 队列与 TCP HTTP 对端核对正文/编号；同数据目录的宿主停止、卸载/不兼容模块及重新注册属于软件验证，不等于实物、断电或完整网页闭环。

## 配置路径与边界

1. `GET /api/edge-admin/v1/input-modules` 列出已安装 kind/version/声明；所有已登录角色可读，响应不缓存。没有模块时，设备页不提供新建扩展输入，已有草稿仍可读取。
2. 在设备页选“扩展输入”及明确模块类型；来源页选择明确版本，再通过自动表单配置。不会自动采用最新版本或填入未确认默认值；用户明确切换版本时才以新声明默认值重置。参数不含凭证。
3. 必填/范围错误、目录查询失败或所选版本被移除时禁止保存，保留未保存编辑。后台刷新不覆盖参数；精确 JSON 数字通过词法读写保留，不经过浏览器浮点数转换。
4. 在路线画布添加对应版本的输入节点，从真实来源目录选择引用并连线。来源与节点必须同时匹配 kind/version；可手工样本预览和运行缓存预览，但不会凭页面打开自动 Build/采集/外发。
5. 保存来源会短事务读取、事务外描述/字段检查、短事务复核版本后原子保存/审计。错误资源归属在执行扩展代码前拒绝；同设备字段 key 不可重复。描述期间其他人修改草稿时，本次写入因版本冲突拒绝。
6. 设备复制及配置导出保留类型、版本、精确参数；跨网关导入按原业务 key 重映射 ID，缺模块/版本或字段/引用错误则整次拒绝。模块卸载后仍可读取/导出原草稿，不把它当空配置或替换成内置来源。

实际软件、网页与浏览器验证以[实施状态 §2.270](implementation-status.md#2270-t3-10-输入模块草稿自动表单与真实网页链路2026-10-18)为准；它不是完整 T3、硬件兼容或扩展开发指南验收。

## 连接引用与冻结运行

`inputModule.connections` 是按声明参数名索引的冻结对象，每项含 `connectionId`、`kind`、`configuration`。对应 `parameters` 中的值仍为规范十进制 ID **字符串**，必须与快照 ID 一致；不是用户可移植导入文件，也不允许把内部 ID 直接导出到其他网关。

- 支持多个声明引用；缺绑定、错 ID/协议、未声明绑定均在 Describe/Build 前拒绝。可选引用为空时不需要绑定。最多128项，connections 整体最多128 KiB；原标量参数仍独立受128 KiB限制。
- `kind` 支持 `http`、`mqtt`、`modbus`。HTTP configuration 只包含已有连接的 `baseAddress`、`timeoutMs`、非秘密 `headers`；MQTT 包含主机/端口/TLS/ClientId/超时/保活及非秘密的 `usePassword` 凭证需求标记；Modbus 包含已有物理连接参数，帧格式用字符串枚举。不保存秘密、可信证书材料或活跃客户端；所有现有地址、请求头与超时校验继续适用。
- Host 在新计划和历史结构读取时都校验协议快照；按连接 ID 与内置 HTTP/MQTT/Modbus 一起检查协议/身份冲突和全局配额。模块未安装也不能隐藏连接引用或旁路连接数上限。
- 原 `InputUnitContext.Connections` 提供不可变快照。运行时在逐输入构建失败处理范围内解析一次，原监督者重建沿用同一个 context，不随未应用草稿更新。在 RuntimeHost 构建阶段遇到的引用解析异常只导致对应输入 BuildFailed；这不放宽持久快照的哈希/结构校验，损坏有效快照仍按既有规则阻止运行。
- 模块联网仍须复用原共享连接、受保护凭证解析、出站与 TLS 机制。测试模块委托 DI 中已有的 `HttpInputFactory`，与内置输入/输出实际共用一个 TCP 客户端；没有新建 Host、HTTP 客户端管理器或发送队列。
- 保留版本的连接删除/凭证清除保护、导入新 ID 冲突复核、换址后默认作废凭证均包含模块引用；这些检查不执行模块。新引用不会让历史凭证因为扩展已卸载而可被清除。

HTTP 运行基础见实施状态 §2.271；草稿、可移植引用与自动表单见 §2.272；MQTT/Modbus 原协议委托与关联验证见 §2.273。不把测试模块、API 夹具或正常软件重启视为全流程无代码配置、实物或完整 T3 验收。

### 草稿与可移植格式

- 来源 API 的 `module.parameters` 只保存非引用标量，`module.connections` 单独保存参数名 → 内部连接 ID（安全整数）。两个对象不能有同名属性，即使标量值为 null；也不自动把普通字符串当成连接引用。
- 来源保存先在短事务中读取同一草稿版本的设备、连接和兄弟来源；事务外校验声明并 Describe，最后短事务复核全局版本。引用缺失、协议错误、未声明引用或超限时拒绝，不开始采集。
- 停用连接允许保存在草稿中，但引用它的来源不能编译应用。即使来源停用或模块已卸载，其显式连接引用仍阻止删除该连接；复制设备保留这些引用。
- 导出 JSON 的 `module.connections` 值改为 `connectionKey`，不带内部 ID，不需要模块仍已安装。合并/替换导入都按本地候选连接的业务 key 解析 ID，再使用完整候选连接进行同源校验；缺模块、缺连接、错协议或并发冲突整次拒绝。旧的纯标量模块文件保持兼容。
- 自动表单下拉只列出声明允许的真实连接。连接目录失败、刷新中或其版本与编辑草稿不一致时禁止引用编辑/保存，保留原选择与未保存名称；成功刷新不会自动替换编辑。旧目录中没有的选择明确显示未知，不静默改为第一个连接。选择版本仍须显式操作。
- 单图编译、字段分析和样本预览读取全部模块引用，不限于设备/输出直接引用的连接。只有确认应用才提交为有效计划并启动；未应用的地址改动不改变重启后的有效连接。

以下仅示意同一来源的引用差别；完整文件还须包含设备、连接等配置，模块 kind/version 必须已编译注册：

```json
{"kind":"input.example","version":1,"parameters":{"value":9007199254740993},"connections":{"primary":123}}
```

上面是来源 API 的 `module`；可移植导入导出的对应片段为：

```json
{"kind":"input.example","version":1,"parameters":{"value":9007199254740993},"connections":{"primary":"http-source"}}
```

运行封套则包含规范 ID 字符串参数和非秘密连接快照，不能拿运行快照当作可移植导入文件。

## 复用原协议的输入模块

`IInputModuleFactory.BindProtocol(parameters, connections)` 可返回 `InputProtocolBinding`，内容是已有 `input.http`、`input.mqtt` 或 `input.modbus` 的完整非秘密配置。它与 Describe 一样只做本地计算、支持并发、不访问网络/数据库，不应存储每次调用的可变状态；不在配置写事务中执行。模块仍是编译期受信任代码，不是运行脚本或热加载插件。

- 委托配置须引用已声明、同协议的 connectionId；不能隐藏另一连接、递归委托模块或绕过内置字段/秘密校验。单份协议配置最多 1 MiB。
- 编译把委托冻结为 `inputModule.protocol = { kind, configuration }`。准入/构建核对该版本模块重新描述的配置哈希；代码行为变化不能悄悄改变旧版本。同 key 的运行单元 ID 仍是原模块 kind，设备归属、输入上下文和队列都不变。
- 每次 Prepare 只调用原计划 provider 一次，模块工厂视图绑定该次原工厂，不另建 MQTT/Modbus 工厂、共享连接管理器或后台服务。委托时不调用模块 Build/RecoveryGroup，使用原协议工厂的构建和恢复分组；模块 UsesDurableHandoff 必须与原工厂一致。
- MQTT 模块与内置输入/输出共用原连接分组、启动屏障、订阅及持久接管确认；必须声明 `UsesDurableHandoff = true`。Modbus 模块使用原物理连接/从站串行协调及停止预算。HTTP 也可使用同一委托入口；原有自包含和自定义 HTTP 模块仍可返回 null 并执行自己的 Build。
- MQTT/Modbus 引用没有委托时拒绝，不回退到不受协调的模块 Build。一次委托对应一个原协议输入；不宣称支持在一个模块中组合多个主动协议循环。
- 冻结的委托和全部引用纳入连接身份冲突、MQTT 反馈环、全局/Modbus 配额、历史删除与凭证保护；历史读取不调用模块。原凭证解析、出站和 TLS 校验不变。
- 运行设备诊断从冻结委托获取轮询周期；Modbus/HTTP 保留过期规则，MQTT 仍归类为推送来源，不把连接正常当成传感器在线。接口保留模块自己的 kind，不改成内置类型。

验证使用测试侧编译期模块及真实 Mosquitto、软件 Modbus 从站、HTTP 接收端。网页场景的连接/图是 API 夹具，模块选择、引用/参数编辑、预览及确认应用使用真实页面；不称为完全无 API 的用户闭环。完整扩展示例/开发指南仍属于 T5-06，输出/新连接类型扩展及 T3 整体验收尚未完成。
