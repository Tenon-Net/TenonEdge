# 输入模块配置与运行接线（T3-10 子项）

当前接通**编译期注册 → 发现与设备/来源自动表单 → 草稿/导入/图编译/预览 → 冻结计划 → 原输入监督者、通道与持久队列 → HTTP 输出**。测试模块仅存在于测试程序集，不作为新业务协议发布。

自包含标量输入已接通网页链路；HTTP 连接引用新增冻结计划/运行基础，尚未接通来源草稿、导入重映射与自动表单。MQTT/Modbus 的模块连接引用及输出/新连接类型扩展仍未完成。**T3-10 和 T3 仍未完成**；完整扩展示例与开发指南仍属 T5-06。

## 注册与契约

- 实现 `IInputModuleFactory`，沿用原 `IInputUnitFactory` 的实例生命周期。通过 Host 编译期 DI 只注册 `IInputModuleFactory` 一次；`InputModuleCatalog` 为同一种 kind 的所有版本提供一个原工厂视图，不再重复注册为 `IInputUnitFactory`。
- `Kind` 必须以 `input.` 开头，遵循 `RuntimeUnitId` 的小写字母/数字、点分段规则（最长 64 字符，**不接受连字符**）。同 kind/version 不可重复，不覆盖现有 simulator/http/mqtt/modbus；不同版本可以同时安装，精确选择，不自动升级旧快照。
- 工厂提供正整数 `Version`、公开 `DisplayName`、Input 用途的 `ParameterSchema`，以及纯本地 `Describe(JsonElement)`。字段含 key、类型、可选单位；最多 1000 个，不可重复或含非法标识/类型。
- 声明先校验，再调用 Describe；描述不构建实例，不访问网络/数据库。工厂是受信任、支持并发调用的代码，不是沙箱；参数/字段/异常不能携带秘密。默认值不隐式注入。
- 来源草稿/自动表单当前接通自包含的文本、数字、开关、选项参数。输入不能声明凭证；目录已接受连接引用声明，运行封套须同时提供对应的冻结快照，缺绑定不能准入。当前 Host 只开放 HTTP 快照；MQTT/Modbus 须接通原计划级订阅/从站协调后再开放，**这是未完成范围，不是最终扩展限制**。不能以地址或秘密标量绕过连接引用。
- `Build` / `RecoveryGroup` 收到去掉封套后的原参数，运行单元 ID 和原 `InputUnitContext` 保持不变。原上下文提供激活屏障、时间、读取状态、有界输入通道与共享预算，不新建后台宿主或发送队列。
- 同 kind 的各版本须采用相同 `UsesDurableHandoff`；可重投输入使用原 `ProduceConfirmedAsync`，只在明确接管/拒绝后按协议确认，不能将进入内存当成持久接管。

## 冻结格式

运行计划的输入单元示意（不是网页导入文件，示例 kind 需自行编译注册）：

```json
{
  "kind": "input.example",
  "key": "meter/source",
  "configuration": {
    "inputModule": {
      "version": 3,
      "parameters": { "value": 9007199254740993 },
      "fields": [{ "key": "value", "type": "integer", "unit": "count" }]
    }
  }
}
```

- `configuration` 只允许 `inputModule`；封套包含正整数 version、parameters，以及可选 fields、connections。参数必须是标量对象，最多 128 KiB；数字保留原文，不经浮点转换。
- 草稿编译时由模块 Describe 冻结并按 key 排序 fields；字段只含非秘密 key/类型/单位。诊断从有效快照读取这些字段，不在 GET 执行模块或从未应用草稿回填。运行准入会核对冻结字段与该版本模块的实际描述一致；不一致时拒绝，不默默换类型。
- 原两属性封套继续兼容；旧种子没有 fields 时不凭空回填或改写历史。
- 旧内置输入与内部工厂的原配置保持兼容，不迁移原快照或哈希。
- 新种子、冻结（含应用/回滚/恢复）和人工重试都重新用当前宿主目录校验。另一目录已解析的计划、历史读取结果不能绕过新冻结；模块代码在配置写事务之前执行。
- 历史读取先核对哈希，再做结构校验，不调用已卸载的模块，不把缺模块当作快照损坏或空配置。
- 重启加载有效快照时，缺模块/缺版本、描述或构建失败由原 Prepare **仅停用该输入单元并显示构建失败**；其他输入和原冻结队列发送继续。重新安装正确版本后，按原有效快照启动，不改历史或重新生成已入队报文。
- 新配置的准备阶段仍是全量准入：任一单元不能构建，不能提交成有效版本；运行后单元异常继续由原监督者按既有停止、释放、退避和单实例规则处理。

验证证据统一记录在[实施状态](implementation-status.md)。本子项的独立输入产生精确整数，经真实 SQLite 队列与 TCP HTTP 对端核对正文/编号；同数据目录的宿主停止、卸载/不兼容模块及重新注册属于软件验证，不等于实物、断电或完整网页闭环。

## 配置路径与边界

1. `GET /api/edge-admin/v1/input-modules` 列出已安装 kind/version/声明；所有已登录角色可读，响应不缓存。没有模块时，设备页不提供新建扩展输入，已有草稿仍可读取。
2. 在设备页选“扩展输入”及明确模块类型；来源页选择明确版本，再通过自动表单配置。不会自动采用最新版本或填入未确认默认值；用户明确切换版本时才以新声明默认值重置。参数不含凭证。
3. 必填/范围错误、目录查询失败或所选版本被移除时禁止保存，保留未保存编辑。后台刷新不覆盖参数；精确 JSON 数字通过词法读写保留，不经过浏览器浮点数转换。
4. 在路线画布添加对应版本的输入节点，从真实来源目录选择引用并连线。来源与节点必须同时匹配 kind/version；可手工样本预览和运行缓存预览，但不会凭页面打开自动 Build/采集/外发。
5. 保存来源会短事务读取、事务外描述/字段检查、短事务复核版本后原子保存/审计。错误资源归属在执行扩展代码前拒绝；同设备字段 key 不可重复。描述期间其他人修改草稿时，本次写入因版本冲突拒绝。
6. 设备复制及配置导出保留类型、版本、精确参数；跨网关导入按原业务 key 重映射 ID，缺模块/版本或字段/引用错误则整次拒绝。模块卸载后仍可读取/导出原草稿，不把它当空配置或替换成内置来源。

实际软件、网页与浏览器验证以[实施状态 §2.270](implementation-status.md#2270-t3-10-输入模块草稿自动表单与真实网页链路2026-10-18)为准；它不是完整 T3、硬件兼容或扩展开发指南验收。

## HTTP 连接引用运行基础（草稿/网页接线尚未完成）

`inputModule.connections` 是按声明参数名索引的冻结对象，每项含 `connectionId`、`kind`、`configuration`。对应 `parameters` 中的值仍为规范十进制 ID **字符串**，必须与快照 ID 一致；不是用户可移植导入文件，也不允许把内部 ID 直接导出到其他网关。

- 支持多个声明引用；缺绑定、错 ID/协议、未声明绑定均在 Describe/Build 前拒绝。可选引用为空时不需要绑定。最多128项，connections 整体最多128 KiB；原标量参数仍独立受128 KiB限制。
- 当前 `kind` 只允许 `http`；其 configuration 只允许已有 HTTP 连接的 `baseAddress`、`timeoutMs`、非秘密 `headers`。不保存路径、秘密、可信证书材料或活跃客户端；所有现有地址、请求头与超时校验继续适用。
- Host 在新计划和历史结构读取时都校验协议快照；按连接 ID 与内置 HTTP/MQTT/Modbus 一起检查协议/身份冲突和全局配额。模块未安装也不能隐藏连接引用或旁路连接数上限。
- 原 `InputUnitContext.Connections` 提供不可变快照。运行时在逐输入构建失败处理范围内解析一次，原监督者重建沿用同一个 context，不随未应用草稿更新。在 RuntimeHost 构建阶段遇到的引用解析异常只导致对应输入 BuildFailed；这不放宽持久快照的哈希/结构校验，损坏有效快照仍按既有规则阻止运行。
- 模块联网仍须复用原共享连接、受保护凭证解析、出站与 TLS 机制。测试模块委托 DI 中已有的 `HttpInputFactory`，与内置输入/输出实际共用一个 TCP 客户端；没有新建 Host、HTTP 客户端管理器或发送队列。
- 保留版本的连接删除/凭证清除保护、导入新 ID 冲突复核、换址后默认作废凭证均包含模块引用；这些检查不执行模块。新引用不会让历史凭证因为扩展已卸载而可被清除。

本次仅后端运行子项，验证记录见实施状态 §2.271；不把种子计划软件验证写成来源草稿、可移植导入、网页配置或完整 T3 验收。下一步须在来源持久化中明确记录引用参数，导出使用业务 key，导入按同版本真实连接重映射并冻结，然后再接自动表单。
