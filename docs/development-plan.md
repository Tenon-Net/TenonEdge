## 3. 第一阶段 T0：工程基础与关键依赖验证

### 3.1 目标、范围与批次

目标：在干净测试环境启动最小后端，通过真实 API 完成初始化和登录；数据目录、账号、身份与密钥在重启和约定的部署变化后仍正确；构建、测试和依赖验证可重复执行。

范围：总设计 §12 的 T0、开发准备 §5 中属于 T0 的子项，以及 BE-D01 §7 的基础工程验收。只创建任务实际用到的工程和类型，四工程是职责边界，不要求第一批建齐四套空项目。

不做：正式采集调度与发送队列业务、完整连接/设备/点位 CRUD、路由编译器与画布、TenonIoT 业务、网页升级、企业模块。MQTT/Modbus 探针放在测试或清晰标识的验证代码中，不宣称正式适配器完成。

| 批次 | 任务 | 本批退出结果 |
|---|---|---|
| T0-A | T0-01—T0-03 | 工程可构建，实际用例可执行，最小宿主可启动、OpenAPI 可生成 |
| T0-B | T0-04—T0-09 | 数据目录、配置库、身份密钥与真实登录权限可用，审计可查 |
| T0-C | T0-10—T0-13 | 必要契约和协议原型有结论，独立发布通过，列出遗留和 T1 准入 |

批次是默认交付顺序，不抹掉实际依赖。T0-10—T0-12 在前置满足后可并行，结果在 T0-C 汇总；共享契约、包版本和启动注册由同一集成人协调。

### 3.2 T0-A：最小工程

#### T0-01 工程与公共构建设置

**前置：** 阅读 AGENTS、本文及所引用基线；检查分支和未提交修改，不覆盖既有工作。

**主要内容：** 建立当前需要的解决方案与最小 Host，按四工程边界添加有实际用途的项目。按 BE-D01 统一 SDK、目标框架、包版本、锁文件和格式。建立 implementation-status，登记本批范围。

**交付物：** 解决方案、必要项目、global.json、Directory.Build.props、Directory.Packages.props、实际还原生成的锁文件、.editorconfig、实现状态入口。

**验收：** locked restore 与 Release 构建成功；SDK 和包清单可追溯；无无用占位工程、私有依赖或前端工程。不能以“目录齐全”代替完成。对应 BE-AT-01/04/07、V-01 环境部分。

#### T0-02 测试底座与初始 CI

**前置：** T0-01。

**主要内容：** xUnit/VSTest 入口、独立临时目录/动态端口辅助、工程依赖方向检查和 Linux CI。先执行工程规则等有实际断言的用例；API 测试在 T0-03 后接入，不提前实现业务。

**交付物：** UnitTests、按需要建立的 IntegrationTests、测试辅助代码、CI 配置和报告规则。

**验收：** 实际发现并执行非零用例；临时构造违规引用或失败断言时检查能失败，提交前恢复正确版本；测试不访问生产数据，失败不被脚本吞掉。对应 BE-AT-01/04/05/07。

#### T0-03 最小宿主、健康检查与 API 模板

**前置：** T0-01、T0-02。

**主要内容：** 启动装配、健康端点、分组 Minimal API、ProblemDetails 与 OpenAPI。尚无有效配置时的就绪语义按总设计 §10.1；管理入口默认受保护，不为演示开放匿名业务写接口。

**交付物：** 可运行 Host、端点映射与统一错误机制、API 测试；测试专用端点不进入生产发布物。

**验收：** healthz/readyz 与实际状态一致；OpenAPI 可生成，operationId 唯一；错误不是 200 包装失败；Program.cs 不堆全部业务。真实登录及完整 401/403 在 T0-07/08 补齐，不因本任务通过而视为完整认证通过。对应 V-01 最小宿主、BE-AT-02 基础。

### 3.3 T0-B：持久化与管理基础

#### T0-04 数据目录与单实例锁

**前置：** T0-03。

**主要内容：** 绝对路径、目录检查、独占锁与释放；取得锁后才能打开运行数据。主机侧维护命令复用同一锁。

**交付物：** 数据目录和锁实现、双进程与退出恢复测试。

**验收：** 同目录第二实例被拒；正常退出/终止进程后可重新取锁；工作目录变化不创建另一套数据；路径错误明确报告。对应 AT-10 单实例子项、BE-AT-03，不算完整队列重启验证。

#### T0-05 配置库与版本化迁移

**前置：** T0-04；D-09 在依赖锁定前按开发准备处理，未决问题记录影响，不自行换 ORM。

**主要内容：** 验证 SqlSugarCoreNoDrive 与 Microsoft.Data.Sqlite 组合；建立本阶段必需实体和迁移；确定物理连接 PRAGMA、并发/事务归属，检查实际 SQLite 原生版本。

**交付物：** 配置访问、迁移、连接设置、真实文件数据库测试及直接/传递依赖记录。

**验收：** 版本、compile_options 和 PRAGMA 有回读证据；符合既定版本下限，WAL/FULL 与连接策略有效；迁移不重复执行、不静默清空，失败保留可诊断状态。对应 V-06/07 开发环境部分、BE-AT-04/05；发布环境在 T0-13 复验。

#### T0-06 身份、ID、密钥与初始证书

**前置：** T0-05。

**主要内容：** NodeId、configStoreId、ID 生成器、持久化密钥环和自签证书；验证保护/解密、路径变化和挂卷重建；检查容器数据目录持久化条件。

**交付物：** 初始化与秘密保护实现、身份/密钥测试、ID 来源记录。只建立保护基础，不提前完成全部连接凭证业务。

**验收：** 身份重启保持；换路径、重建挂卷容器后可解密；不满足持久目录条件时按设计拒绝启动运行时；时钟回退和重启后的 ID 符合 §10.1；秘密不入源码和日志。对应 V-08/13、AT-19 密钥子集、BE-AT-05/06。

#### T0-07 首次设置、登录与主机重置

**前置：** T0-05、T0-06；D-01、D-02 在接口定稿前收束，未确认时按现行规则实现并保留待调整状态。

**主要内容：** 设置窗口/状态、管理员创建、密码哈希、登录登出、必要改密和临时密码状态、主机重置；同步接入最小审计写入。不实现前端或完整用户管理页面。

**交付物：** 真实认证 API、重置命令和测试，无默认/演示账号。

**验收：** 并发初始化仅一次成功；窗口外拒绝；初始化后重启不再开放；弱口令拒绝，错误登录受限，无明文密码存库；重置遵守锁与现行规则并记审计。对应 GW-01、AT-24、功能 §1；API 通过不等于网页完成。

#### T0-08 角色、会话失效与请求安全

**前置：** T0-07。

**主要内容：** 固定三角色、Cookie 与防 CSRF、受信任代理、限流、安全戳/会话代次；开启作用域与注册验证。角色测试数据由测试夹具初始化，不增加生产后门。

**交付物：** 集中安全策略、API 及必要的真实网络测试。

**验收：** 未登录 401、无权 403；Cookie 写操作校验防 CSRF；伪造转发头不生效；HTTP/HTTPS 会话不能互换；角色/密码等变化使旧会话失效；不重复创建运行时。对应 V-11 T0 子集、BE-AT-02/03；Token 和完整浏览器场景后续回归。

#### T0-09 审计、基础日志与降级记录

**前置：** T0-05、T0-07、T0-08；复用 T0-07 的审计写入，不造第二套机制。

**主要内容：** 完善已实现操作的审计、查询授权、保留清理和结构化日志；建立供 T1 使用的运行事件最小存储；按总设计处理写入失败。

**交付物：** 审计/日志基础、集成测试和脱敏说明。运行事件生产者随模块落地，趋势和完整诊断不提前实现。

**验收：** 重启可查，权限正确；初始化/登录/重置有证据；密码、Token、私钥不入日志；存储异常可测，不无限写日志耗尽磁盘。对应功能 §9 基础、BE-AT-05/07。

### 3.4 T0-C：契约、依赖与发布验证

#### T0-10 必要运行契约与基础数值测试

**前置：** T0-01、T0-02；Host 生命周期测试依赖 T0-03。可在 T0-B 并行。

**主要内容：** 只定义有明确使用者和测试的 RuntimePlan、消息、只读边界契约；验证构建/启动分离、作用域与实例唯一性、JSON 基础数值表示。

**交付物：** 最小契约、测试适配器/替身和数值测试。监督、队列、启动保护在 T1，完整图编译与应用在 T3。

**验收：** 构建不联网、不采集；无 Host/ORM/协议类型泄入契约；请求后不使用释放的上下文；大整数、decimal/float、非有限值符合既定表示。对应 V-12、BE-AT-01/03，AT-30 端到端仍在后续。

#### T0-11 MQTT 最小原型

**前置：** T0-02；可与配置/认证并行，公共依赖修改须协调。

**主要内容：** 锁定候选版本，用真实 Broker 和独立订阅者验证 3.1.1 发布、PUBACK、超时、持续发布中断线检测、TLS；记录持久会话/手动确认的最小探针。

**交付物：** 可复现验证代码、测试 Broker 配置、版本与行为结论，不宣称正式适配器完成。

**验收：** 实际收到已知内容；延迟/断开受超时控制；错误证书拒绝，显式信任路径可测；异常库行为与所需包装有记录。对应 V-04 的 T0 部分；完整输入背压、保留消息、会话恢复在 T2。

#### T0-12 Modbus 候选库比较

**前置：** T0-02；可与 T0-11 并行。

**主要内容：** 同一模拟从站测试分别验证 NModbus、FluentModbus 的 TCP/RTU over TCP、超时、停止、忙响应、事务号和迟到应答。

**交付物：** 比较测试、版本/来源、适配层待补行为与选型结论或具体阻塞项。

**验收：** 不以连通或一次读取作为完整通过；关键差异有可复现结果，未满足项明确，不声明全部设备兼容。对应 V-05 比较部分；全类型/字节序及完整适配在 T2-02。

#### T0-13 独立发布与阶段证据汇总

**前置：** T0-01—T0-12 的本阶段工作均有状态和证据；原型的完整 T2 场景不提前要求通过。

**主要内容：** 完善 Linux CI、自包含最小发布、干净环境启动和持久化复验；补齐 V-02/09/10 的 T0 资料核查，不创建前端；汇总协议、依赖、许可待核查与阶段结论。

**交付物：** 测试发布物、实际 CI 报告、implementation-status、reference-notes 和遗留条件；不是 T5 完整安装包或整机认证。

**验收：** 未预装 .NET 的干净 Linux 环境可启动；SQLite 和密钥实际行为复验；locked restore、Release 构建及非零用例有证据；失败和跳过不写为通过。对应 V-01/06—08/11—13 的 T0 范围、BE-AT-01—07 基础。

### 3.5 T0 退出与进入 T1

验收演示：新测试目录启动 → API 初始化 → 登录与授权 → 重启后身份/账号保持 → 路径/容器变化可解密 → 重复实例被拒 → CI 与独立发布可复现。未实现的网页、协议和队列不得作为已完成能力演示。

退出报告区分“本阶段工作已执行”和“可以进入 T1”。前者要求 T0 子项有真实状态，后者沿用开发准备 §1：V-01/06/07/08 有结论且没有阻塞性未通过项；V-04 的发布超时、断线检测和证书校验在 MQTT 输出实现前有结论；D-07 正式确认；D-05 在连接与凭证 API 定稿前确认。依赖失败不能仅靠记录原因视为通过，须修复或获明确替代方案批准。

D-01、D-02、D-09 按对应任务记录，不擅自批准。V-04/V-05 后续完整测试、前端浏览器、真实平台和实物断电不成为额外 T0 前置门槛；遗留项明确阻塞哪个任务。

## 11. 任务分派与完成定义

### 11.1 任务卡格式

可使用本文段落或建立同 ID 的 Issue，不另造命名。每次分派至少包含：

```text
任务 ID / 名称：
所属阶段与批次：
基线提交 / 工作分支：
实现负责人 / 集成或验收人：
前置任务与待确认决策：
目标、涉及目录、明确不做的内容：
交付物：
验收编号、子场景、步骤与预期结果：
代码/文档状态：
测试命令、实际环境、结果和证据位置：
阻塞、跳过与剩余风险：
本次停止点 / 是否获准开始下一任务：
```

负责人在分派时填写，Agent 自报完成不等于验收人认可。任务过大按同 ID 分子任务，每项可构建且带测试；共享分支不并发覆盖版本、契约和启动文件。

### 11.2 统一完成定义

登记完成需同时满足：范围内实现实际存在；所需构建/测试执行有证据；失败处理；不适用有原规则依据；接口/依赖变更说明；无秘密泄露或范围扩张；文档/implementation-status 同步；指定验收人检查。

环境不足可阻塞或跳过，继续独立任务，但依赖该证据的任务不能整体写完成。不能只测成功路径，负向、释放、权限和持久化不得省略。破坏性故障测试只针对隔离进程、临时目录和测试环境。

### 11.3 默认执行节奏

第一轮只分派 T0-A（T0-01—T0-03），交付变更清单、命令、非零报告和启动证据后停止验收；通过后 T0-B，再 T0-C。协议原型可依赖满足后并行，公共依赖由集成人落地。

每批优先小变更，不把整个 T0 做成一次不可审查的大改。任务授权与 Git 提交/推送/发版授权分开：无明确许可不提交推送、不发版、不改其他仓库。

首轮指令示例（实际执行前由维护者分派）：

```text
按当前 AGENTS.md 和 docs/development-plan.md 执行 T0-A，
本轮只做 T0-01、T0-02、T0-03。
保留工作区现有修改，以实际基线为准。
交付可构建最小后端、真实测试和 Linux CI，不只建空目录。
不创建 web/、完整协议适配器、发送队列、画布、平台或升级功能。
建立 implementation-status，记录实际环境、命令与结果；
缺少环境或未运行的验证如实标注。
批次结束汇报证据和阻塞项，不自动进入 T0-B 或 T1。
未经另行授权，不提交或推送。
```

本次文档更新只建立任务清单与开发入口；编码任务仍未开始，项目测试仍未执行。
