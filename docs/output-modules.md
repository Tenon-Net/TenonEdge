# 输出模块配置与运行

对应 T3-10 / 功能需求 §12.2。本页描述当前已接入的后端和网页子项，验证证据见[实施状态 §2.274](implementation-status.md#2274-t3-10-输出模块原协议委托与目标保护2026-10-18)及 §2.277—§2.278、§2.299。**发现 API、图草稿/编译/导入导出和网页自动表单已接入；HTTP/MQTT 委托的预览及原一次发送已接入；扩展传输的网页配置/发送/正常重启已验证一个软件子场景。扩展传输纯预览、凭证与迁移组合仍未完成，不代表 T3-10 或 T3 验收完成。**

## 编译期声明

实现 `IOutputModuleFactory` 并在宿主 DI 注册该接口；不要再把同 kind 注册为 `IOutputAdapterFactory`。目录自动接入原 RuntimeHost，没有第二套运行时、发送队列或后台任务。kind/version 明确且不可重复，不覆盖内置 `output.http`、`output.mqtt`、`output.tenon`。

- `Parameters` 使用原 `ParameterSchema`，scope 为 Output，不允许 Credential 字段。非秘密标量与连接引用仍按同一声明校验。
- `BindProtocol(parameters, context)` 只做纯本地、并发安全计算，返回原 HTTP/MQTT 或已注册扩展传输的完整非秘密配置。不得联网、访问配置写事务或创建客户端/后台循环。
- `OutputModuleContext` 固定目标 ConnectionId、1—2000 个不同的 `deviceKey/inputKey` 来源及按参数名绑定的不可变 `ModuleConnectionSnapshot`。目标必须属于显式引用；委托不得改变目标 ID、协议或来源顺序，也不得递归委托模块。
- 委托不带 mapping、mappingStages 或 transformStages。转换在外层运行单元中，仍由原分发器执行一次；队列接续不是模块路线，不能声明 queueOnly=true。
- 已接入扩展传输的冻结路由、原目标保护与原发送者运行基础（下节），以及显式支持的无路线队列接续。网页配置发送已有 §2.299 子场景，纯预览及完整凭证组合仍未完成；不能用自建发送器绕过原目标保护。

### 输出能力发现

原认证 `GET /api/edge-admin/v1/output-modules` 的每项声明返回 `targetConnectionKinds`：模块的连接引用协议、已安装连接声明、已登记输出传输三者的交集，去重排序。直接工厂使用 `Kind`；计划级 `IRuntimePlanAdapterProvider` 提供静态 `OutputKinds`（MQTT 也使用此途径）。发现不调用 `Create`、`Build`、协议或队列绑定，不创建第二套共享会话。旧 provider 默认空声明，仍可执行已有计划，但不据此向网页宣称可选输出目标。

网页严格验证此能力数组；缺失、类型错误、重复或超出模块引用声明时，不回退到 HTTP/MQTT。扩展连接引用以 `module.kind` 匹配，外壳 `kind=module` 不被当作实际协议。能力失效或刷新期间保留未确认参数和显式目标，禁止旧确认，恢复后由用户核对；选引用不自动选目标。能力声明不能替代编译、凭证、启停或出站校验。

模块是受信任的编译期代码，不是沙箱。没有上传 DLL、热加载或前端插件。

### 新传输的冻结路由

非 HTTP/MQTT 绑定必须在协议配置中声明 `transportRoute`，恰有以下两个字符串字段：

```json
{"transportRoute":{"recipient":"wire://127.0.0.1:19001","addressTemplate":"events/{deviceKey}"}}
```

`wire` 仅为测试侧传输例子，不是产品新增的内置协议。`recipient` 须与已声明连接 kind 和 `output.<kind>` 传输一致，明确端口，不带用户名、查询或片段。地址模板可以是常量或只含 `{deviceKey}`；不接受其他表达式、花括号或控制字符，按所有占位符各展开为最长业务 key 后核对 UTF-8 不超过 4096 字节。

- 冻结历史、待发/失败保护、同连接换址迁移及损坏快照恢复读取这个描述，不在配置事务中调用扩展代码。没有描述的旧历史仍可读取，但不能重新准入，也不能忽略其旧队列。
- 准备时原 RuntimeHost 包装扩展目标，核对实际接收方、捕获的协议/非秘密身份与冻结描述一致。生成报文时检查展开地址、非空指纹及可解析且匹配的身份摘要；不匹配经原分发器拒绝，不接管入库。
- 同一连接的多个输出仍由原共享判断合并为一个发送者。适配器发送每条记录已冻结的地址与字节；**不得在发送时要求旧地址等于当前模板**，否则会破坏管理员显式迁移的保留规则。
- 恢复预检通过原准备入口捕获新传输的真实身份，再检查每条待发/失败记录的指纹和展开地址；不匹配阻止确认，隔离区不被隐式恢复或重写。

实际 TCP 双路径/确认、出站拒绝、正常 Host 重建时缺模块/连接声明/传输工厂/绑定失败，以及恢复模块后原记录补发的测试位于 `ExtensionOutputRuntimeTests`。迁移测试调用原运行时双发送者协调入口，恢复测试使用真实管理 API；不冒充网页迁移或进程强杀验收。完整证据和未完成项统一见实施状态。

### 无路线的发送接续

直接注册的扩展 `IOutputAdapterFactory` 可实现 `BindQueueOnly(ModuleConnectionSnapshot)`，返回完整的非秘密协议配置；默认返回 null，表示没有这项能力。它只做确定性的本地计算，不读取凭证、不联网、不创建传输实例或生成报文。内置 HTTP/MQTT 仍沿用原编译规则和原计划级工厂，不因这项扩展重复创建 MQTT 输入/输出会话。

- 协议配置必须包含原 `connectionId`、`queueOnly: true`、空 `inputs` 及 `transportRoute`。其地址模板必须为空：接续只发送队列记录中冻结的地址，不引入当前格式、映射或新来源。
- 编译器只为启用且没有输出路线使用的连接生成稳定 `queue/<connectionKey>/sender` 单元，不增加拓扑、输入或格式化路径。没有传输工厂或返回 null 时，不把输入型扩展连接猜作输出目标。
- 原目录把连接 kind/version/参数及协议配置一起冻结在 `queueOutput` 中。历史、目标保护和恢复预检只读取结构；**旧完整检查点没有冻结扩展发送配置时，不在重启时调用扩展补生成**，须核对后重新应用。
- 新冻结及运行准备核对当前声明和绑定是否与快照一致；准备还沿用原凭证解析，并检查实际目标不能换 connectionId 或增加来源。声明/工厂缺失或绑定变化时仅降级该发送单元，队列和历史哈希不改。
- 删除最后一条输出路线而保留原接收方时，旧待发记录继续由原发送者处理；换接收方仍被原待发保护阻断。管理员显式迁移到无路线目标仍保留旧地址、正文、seq 和投递编号，不解除暂停。
- 已冻结的接续不依赖原报文格式模块仍然安装，但依赖对应连接声明、传输工厂和当前有效凭证。测试侧真实 TCP、正常 Host 重建、原协调者应用和双发送者迁移证据见实施状态 §2.298；不是网页迁移或独立进程强杀验收。

## 发现声明

`GET /api/edge-admin/v1/output-modules` 向三个已登录角色返回已注册输出模块的 kind、version、显示名及原参数声明；匿名请求拒绝。响应 `Cache-Control: no-store`，按 kind/version 排序，同 kind 的多个版本分别列出。

发现不会调用 `BindProtocol`、编译计划、修改草稿或触发发送。默认产品没有演示输出模块时返回空数组。数字默认值/范围沿用声明的 JSON 原文字符串，不能先转为 JavaScript 数字；输入和输出声明不允许凭证字段。画布按此声明发现模块，不需要为某个新模块添加专用前端代码。

## 图草稿、导入与预览

图节点保存模块自身的 `type`、`version` 和原图内 `id`，参数与显式连接引用分开。下面仅示意节点配置，不是完整导入文件；kind/version 须已编译注册，123 须为本机现有连接：

```json
{"id":"out","type":"output.example","version":1,"name":"Output","config":{"connectionId":123,"parameters":{"address":"events","precision":9007199254740993},"connections":{"primary":123}}}
```

- `connectionId` 是这一个输出的投递目标，必须属于 `connections` 中的某项显式引用。所有引用均参与连接删除保护，不只保护投递目标。编译时还检查连接存在、启用、声明协议、目标身份及原协议配置。
- 保存/复制只做声明及结构检查，不执行模块代码；允许缺必填值等不完整草稿，但不能应用。未知参数、嵌套参数、重复 JSON 属性、混在 parameters 中的引用、非法编号及超限均拒绝。参数数字保留原文，映射/转换仍在外层只执行一次。
- 合并/替换导入导出把 `connectionId` 改为业务 `connectionKey`，把 `connections` 改为参数名 → 业务 key 的 `connectionKeys`。导入拒绝内部 ID（含大小写别名）、缺模块/版本、缺连接和错误协议；导出/历史读取不需要模块仍已安装，也不调用绑定。
- 绑定和计划校验在配置写事务之外；委托生成的 HTTP 查询参数及头也经过与内置节点相同的秘密名称检查。模块改变接收方、返回无效配置或引用不存在的报文字段时，预检及对应预览路径失败，不产生一次发送产物。
- 纯预览不连接目标、不入队。预览结果的 `output.kind` 表示实际传输 `output.http` 或 `output.mqtt`，路径/节点身份仍属于原模块，因而复用原预览 → 准备 → 确认的一次发送入口。确认使用服务端保存的原字节/编号，不入队、不重试、不重复执行映射；丢回复不自动重放。
- 保存后显式应用才启动原输入/输出。正常重启时从完整冻结图恢复诊断标签；输出模块缺失只使该输出构建失败，原队列/有效版本哈希保留。模块恢复后，原 HTTP/MQTT 发送者继续原冻结报文和编号，MQTT 管理员暂停仍须显式恢复。

## 网页自动表单

1. 在路线画布的输出节点库选择已安装模块和版本。表单使用同一声明生成文本、精确数字、开关、选项和连接引用；节点参数不包含凭证。
2. 先选择声明允许的连接引用，再显式选择“模块投递目标”。投递目标只列本模块已引用且具有已安装输出传输能力的连接（含扩展协议），不因选择或移除引用而自动改换接收方。停用连接有明确标识，服务端编译仍阻断。
3. “确认节点配置”只改变当前图，既不保存也不发送。数字默认值、范围和编辑值保留原文；未编辑的 null 和数值类型也不归一化。必填或范围错误可留在草稿，必须修正后才能应用。
4. 模块目录失败、所选版本缺失或声明变化时，保留未确认的表单并禁止确认；连接目录失败、刷新中或版本与路线不一致时同样禁止确认，显式重新读取后再核对。原始配置不能自动编辑时保留 JSON，不替换成默认值。
5. HTTP/MQTT 委托保存后可用原纯预览核对报文，再通过原准备/确认入口测试发送一次；扩展传输纯预览尚未接入，也不提供测试发送；正常转发仍须在配置页明确应用。只读角色能查看非秘密配置，不能编辑、预览或发送；API 独立检查角色。

网页新增、撤销重做、故障查询保护、真实 HTTP/MQTT 一次发送、应用与重启子场景见 §2.278。测试中的连接、模拟来源及输入→映射图为 API 夹具，输出节点和表单由真实浏览器创建；这不是无 API 配置全流程或完整 T3 验收。

## 冻结、构建与发送

运行配置外层保存 `connectionId`、`inputs` 和可选转换阶段；`outputModule` 内保存 version、parameters、connections，以及冻结的 protocol（kind/configuration，最多 1 MiB）。参数和连接分别沿用 128 KiB 上限。引用参数为规范十进制 ID 字符串，与对应 connectionId 一致。这是内部运行格式，**不是可移植导入文件**。

1. 新计划准入重新调用纯绑定，核对规范化协议配置哈希；内置HTTP/MQTT及新连接传输适配器分别校验自己的冻结配置。模块kind只可委托原内置`output.http`/`output.mqtt`，或显式登记且与连接kind匹配的`output.<connection-kind>`工厂。新传输的工厂只负责构建原`IOutputTarget`，发送适配器必须经原`ISharedConnections`租约和`IOutboundConnector`实际地址检查，并按需使用`IModuleCredentialResolver`逐次读取材料；不得自建监督者/队列或从未经检查的DNS结果建连。新配置冻结、人工重试及启动保护自动回滚均检查已安装的精确版本；模块代码在配置写事务外执行。
2. 历史读取只检查冻结结构和原协议配置，不运行模块，也不读取未应用草稿回填。原连接身份冲突、凭证保护、MQTT 反馈环及计划规模限制包含这些引用。
3. 每次 Prepare 只创建一次原协议 provider；输出模块与同计划的输入/内置输出绑定到这一套工厂。原输出保留模块的运行单元 ID；目录验证实际目标的 ID、ConnectionId 与 Inputs 没有改变。
4. 同连接输出仍共用一个原发送者；MQTT 与输入共用原恢复组/会话和持久确认。报文生成、入队、冻结、超时、暂停、重试、出站检查及 TLS/凭证均沿用原实现。新适配器须定义完整且稳定的接收方身份摘要；未知账户/旧身份不能从当前草稿补写，迁移仅接受同一传输协议且由管理员声明同一所有者，原协调者双发送者屏障、隔离和收据继续生效。
5. 启动时模块缺失、版本不支持或绑定变化只使该单元构建失败，不阻断其他输入，不删除原冻结记录。正确模块恢复后，按旧报文和编号继续发送。损坏快照仍阻止运行，不解释成空配置。

## 原目标保护

- 存在待发/失败记录时，删除目标、更换接收方或更改 Topic/path 仍受原变更保护限制；模块与内置节点之间互换不改变同一实际目标的判断。
- 已确认的同连接换址迁移只允许原协议和路径保持一致，不允许把 Topic/path 变化夹带进迁移声明。
- 发送者记录来自冻结计划的协议类别，迁移时不把模块 kind 当作传输协议，也不单凭适配器自报身份放宽检查。内置与模块目标可经原双发送者静默机制同协议迁移；不解除管理员暂停，不重写正文、编号或冻结路径。
- 损坏快照受限恢复继续核对完整历史、原目标指纹及每条冻结路径；MQTT 占位符按原 deviceKey 展开。模块输出已经覆盖目标时，不额外生成可能放宽路径核对的 queue-only 单元。

`InputConnectionSnapshot` 在这批开发中统一命名为 `ModuleConnectionSnapshot`，输入模块相关方法的源码类型同步调整；冻结 JSON 格式未变。未承诺旧开发中接口的二进制兼容，已有源码扩展需要更新类型名并重新编译。

## 验证边界

测试模块仅在测试工程注册，默认产品不内置演示输出模块。验证包括纯声明/历史准入、图草稿与跨 Host 业务 key 导入、真实 SQLite 目标变更和恢复核对、真实 TCP HTTP 投递/冻结重启/迁移，以及真实 Broker 上的 MQTT 输入与双输出共享。图草稿显式应用、预览后一次确认、缺模块正常重启与恢复冻结发送的证据见 §2.277。输出模块网页子场景见 §2.278；这些是软件和浏览器验证，不是实物断电、第三方设备兼容或完整 T3 验收。
