# 输出模块运行基础

对应 T3-10 / 功能需求 §12.2。本页描述当前已接入的后端子项，验证证据见[实施状态 §2.274](implementation-status.md#2274-t3-10-输出模块原协议委托与目标保护2026-10-18)及 §2.277。**发现 API、图草稿/编译/导入导出/预览及原一次发送已接入；网页画布选择/自动表单、新连接类型扩展仍未完成，不代表 T3-10 或 T3 验收完成。**

## 编译期声明

实现 `IOutputModuleFactory` 并在宿主 DI 注册该接口；不要再把同 kind 注册为 `IOutputAdapterFactory`。目录自动接入原 RuntimeHost，没有第二套运行时、发送队列或后台任务。kind/version 明确且不可重复，不覆盖内置 `output.http`、`output.mqtt`、`output.tenon`。

- `Parameters` 使用原 `ParameterSchema`，scope 为 Output，不允许 Credential 字段。非秘密标量与连接引用仍按同一声明校验。
- `BindProtocol(parameters, context)` 只做纯本地、并发安全计算，返回原 HTTP/MQTT 输出的完整非秘密配置。不得联网、访问配置写事务或创建客户端/后台循环。
- `OutputModuleContext` 固定目标 ConnectionId、1—2000 个不同的 `deviceKey/inputKey` 来源及按参数名绑定的不可变 `ModuleConnectionSnapshot`。目标必须属于显式引用；委托不得改变目标 ID、协议或来源顺序，也不得递归委托模块。
- 委托不带 mapping、mappingStages 或 transformStages。转换在外层运行单元中，仍由原分发器执行一次；队列接续不是模块路线，不能声明 queueOnly=true。
- 当前子项只支持委托已有 HTTP/MQTT 协议。新传输/连接类型仍是待完成的扩展能力，不能把这个阶段性接口当成最终范围，也不能用未描述的自建发送器绕过原目标保护。

模块是受信任的编译期代码，不是沙箱。没有上传 DLL、热加载或前端插件。

## 发现声明

`GET /api/edge-admin/v1/output-modules` 向三个已登录角色返回已注册输出模块的 kind、version、显示名及原参数声明；匿名请求拒绝。响应 `Cache-Control: no-store`，按 kind/version 排序，同 kind 的多个版本分别列出。

发现不会调用 `BindProtocol`、编译计划、修改草稿或触发发送。默认产品没有演示输出模块时返回空数组。数字默认值/范围沿用声明的 JSON 原文字符串，不能先转为 JavaScript 数字；输入和输出声明不允许凭证字段。该 API 的存在不表示画布已能选择输出模块。

## 图草稿、导入与预览

图节点保存模块自身的 `type`、`version` 和原图内 `id`，参数与显式连接引用分开。下面仅示意节点配置，不是完整导入文件；kind/version 须已编译注册，123 须为本机现有连接：

```json
{"id":"out","type":"output.example","version":1,"name":"Output","config":{"connectionId":123,"parameters":{"address":"events","precision":9007199254740993},"connections":{"primary":123}}}
```

- `connectionId` 是这一个输出的投递目标，必须属于 `connections` 中的某项显式引用。所有引用均参与连接删除保护，不只保护投递目标。编译时还检查连接存在、启用、声明协议、目标身份及原协议配置。
- 保存/复制只做声明及结构检查，不执行模块代码；允许缺必填值等不完整草稿，但不能应用。未知参数、嵌套参数、重复 JSON 属性、混在 parameters 中的引用、非法编号及超限均拒绝。参数数字保留原文，映射/转换仍在外层只执行一次。
- 合并/替换导入导出把 `connectionId` 改为业务 `connectionKey`，把 `connections` 改为参数名 → 业务 key 的 `connectionKeys`。导入拒绝内部 ID（含大小写别名）、缺模块/版本、缺连接和错误协议；导出/历史读取不需要模块仍已安装，也不调用绑定。
- 绑定和计划校验在配置写事务之外；委托生成的 HTTP 查询参数及头也经过与内置节点相同的秘密名称检查。模块改变接收方、返回无效配置或引用不存在的报文字段时，预检及对应预览路径失败，不产生一次发送产物。
- 纯预览不连接目标、不入队。预览结果的 `output.kind` 表示实际传输 `output.http` 或 `output.mqtt`，路径/节点身份仍属于原模块，因而复用原预览 → 准备 → 确认的一次发送入口。确认使用服务端保存的原字节/编号，不入队、不重试、不重复执行映射；丢回复不自动重放。
- 保存后显式应用才启动原输入/输出。正常重启时从完整冻结图恢复诊断标签；输出模块缺失只使该输出构建失败，原队列/有效版本哈希保留。模块恢复后，原 HTTP/MQTT 发送者继续原冻结报文和编号，MQTT 管理员暂停仍须显式恢复。

以上是后端 API 和软件链路能力；网页尚不能通过自动表单创建此类输出节点。

## 冻结、构建与发送

运行配置外层保存 `connectionId`、`inputs` 和可选转换阶段；`outputModule` 内保存 version、parameters、connections，以及冻结的 protocol（kind/configuration，最多 1 MiB）。参数和连接分别沿用 128 KiB 上限。引用参数为规范十进制 ID 字符串，与对应 connectionId 一致。这是内部运行格式，**不是可移植导入文件**。

1. 新计划准入重新调用纯绑定，核对规范化协议配置哈希；原协议解析器继续检查未知字段、秘密旁路、地址、超时、报文格式等。新配置冻结、人工重试及启动保护自动回滚均检查已安装模块；模块代码在配置写事务外执行。
2. 历史读取只检查冻结结构和原协议配置，不运行模块，也不读取未应用草稿回填。原连接身份冲突、凭证保护、MQTT 反馈环及计划规模限制包含这些引用。
3. 每次 Prepare 只创建一次原协议 provider；输出模块与同计划的输入/内置输出绑定到这一套工厂。原输出保留模块的运行单元 ID；目录验证实际目标的 ID、ConnectionId 与 Inputs 没有改变。
4. 同连接输出仍共用一个原发送者；MQTT 与输入共用原恢复组/会话和持久确认。报文生成、入队、冻结、超时、暂停、重试、出站检查及 TLS/凭证均沿用原实现。
5. 启动时模块缺失、版本不支持或绑定变化只使该单元构建失败，不阻断其他输入，不删除原冻结记录。正确模块恢复后，按旧报文和编号继续发送。损坏快照仍阻止运行，不解释成空配置。

## 原目标保护

- 存在待发/失败记录时，删除目标、更换接收方或更改 Topic/path 仍受原变更保护限制；模块与内置节点之间互换不改变同一实际目标的判断。
- 已确认的同连接换址迁移只允许原协议和路径保持一致，不允许把 Topic/path 变化夹带进迁移声明。
- 发送者记录来自冻结计划的协议类别，迁移时不把模块 kind 当作传输协议，也不单凭适配器自报身份放宽检查。内置与模块目标可经原双发送者静默机制同协议迁移；不解除管理员暂停，不重写正文、编号或冻结路径。
- 损坏快照受限恢复继续核对完整历史、原目标指纹及每条冻结路径；MQTT 占位符按原 deviceKey 展开。模块输出已经覆盖目标时，不额外生成可能放宽路径核对的 queue-only 单元。

`InputConnectionSnapshot` 在这批开发中统一命名为 `ModuleConnectionSnapshot`，输入模块相关方法的源码类型同步调整；冻结 JSON 格式未变。未承诺旧开发中接口的二进制兼容，已有源码扩展需要更新类型名并重新编译。

## 验证边界

测试模块仅在测试工程注册，默认产品不内置演示输出模块。验证包括纯声明/历史准入、图草稿与跨 Host 业务 key 导入、真实 SQLite 目标变更和恢复核对、真实 TCP HTTP 投递/冻结重启/迁移，以及真实 Broker 上的 MQTT 输入与双输出共享。图草稿显式应用、预览后一次确认、缺模块正常重启与恢复冻结发送的证据见 §2.277。这些是软件验证，不是实物断电、第三方设备兼容或输出模块网页配置能力。
