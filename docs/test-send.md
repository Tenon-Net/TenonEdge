# 通用输出测试发送（T3-07）

当前已接入路线预览输出下的“发送预览测试报文”面板和真实管理 API。不能将本项视为整个 T3 已完成；实际验证见 `implementation-status.md` §2.252。

在路线页选择样本并预览后，点击目标输出下的“核对测试发送”，检查真实目标、可见账号、完整大小/指纹和原编号，勾选确认声明，再点击“确认发送一次”。改变图、草稿版本、来源或样本会关闭旧结果；重新预览、离页或刷新都不会自动发送。取消等待不能撤回对方已经收到的数据。旧确认一经使用（包括回复丢失）即从页面移除，需核对对方后再决定是否重新预览。

## 原预览与确认

1. 配置人员或管理员使用手工、现场 HTTP/Modbus、MQTT 单条抓取或明确选中的运行记录预览路线。预览仍不访问输出、不入队、不保存草稿。
2. 成功输出中的 `testSendId` 是本次完整服务端报文的临时标识。正文显示被截断不等于待测试报文被截断；后续使用服务端原字节，不接受浏览器提交正文或目的地址，也不重新生成消息编号、时间或映射值。
3. `POST /api/edge-admin/v1/routes/test-send/prepare`，提交 `{ "id": "testSendId" }`，核对目标基础地址、认证类型/可见账号、Topic/路径、QoS、原投递/源消息编号、完整字节数和 SHA-256。`previewTruncated=true` 时须明确知道发送的是未截断的完整报文。准备不连接、不解密秘密；再次准备替换旧 `confirmationId`，不延长过期时间。
4. 用户二次确认后向 `/routes/test-send/confirm` 提交 `id`、最新 `confirmationId` 和 `confirmed=true`。禁止自动重试这个请求；页面刷新、回复丢失、网络取消或失败后必须重新核对，不能自动重放。

只有通用 HTTP/MQTT 支持，不给 TenonIoT 提供入口。会话请求需要 CSRF，API Token 仍只可通过 HTTPS 使用；两个入口均执行配置角色授权，临时产物绑定具体会话/令牌，不是绑定账号名。

## 生命周期与资源

- 不落盘、不写运行调试缓存或发送队列；宿主重启全部失效。每个会话只保留最近一次成功计算并登记的预览，另一个标签页的新预览也会替换旧产物。
- 五分钟单调期限，确认只消费一次；后台周期清理过期引用。全局至多 256 条、16 MiB；一次预览至多 128 条、4 MiB，单条保守预算至多 1 MiB（实际输出正文仍不得超过 256 KiB）。预算包括完整正文、非秘密配置、路径和元数据，而非只算截断显示。
- 只保留显示出来的成功输出；省略路径或容量不足时 `testSendId` 为空，仍返回原预览结果，不将其冒充可发送。不会为本会话腾空间而淘汰别人的待确认报文。
- 准备/确认与已有读取一次、抓取、连接测试共用即时准入预算。确认在实际传输及资源清理结束前持有租约，不因请求取消提前释放；网络操作包含排队、连接、发送、响应读取，总期限不超过连接超时及 30 秒操作期限。

## 发送、凭证与结果

- 确认后重新检查草稿版本、凭证身份/版本及接收方绑定，发送开始的短配置事务内再次检查当前操作者、草稿和凭证版本。导入后待补凭证的连接不能借旧秘密测试。不会跨网络等待持有事务。
- 先持久写 `route.testSend.start` 审计，写不成功则不发送；结束写 `route.testSend.complete`，结束审计写失败沿用审计日志降级。只有开始记录时，不能推定发送完成。审计只含安全分类、编号/长度，以及已知 HTTP 状态码或 MQTT Broker 确认标志，不含业务正文、请求头、凭证或对方正文。
- 不入队、不重试。HTTP 复用原串行会话、冻结 POST 编码、幂等编号及当前出站/TLS 校验；MQTT 使用独立随机 ClientId/CleanSession，不替换正式客户端或订阅。
- MQTT QoS 1 明示 Broker PUBACK；QoS 0 仅表示写出，不声称 Broker/业务确认。HTTP 状态码仅表示收到 HTTP 响应，不证明业务落库；完整且通过敏感检查的正文最多读取/显示 64 KiB，按已确认规则隐藏超限、残缺、敏感或不安全正文。正文读取失败仍保留已知状态码。
- 超时、取消、断连、丢回复都不能证明对方没有收到。确认一旦被接管，后续前置检查、审计或传输失败也不恢复旧确认；无自动补发或撤销保证。
